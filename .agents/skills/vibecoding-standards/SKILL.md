## 核心原则（始终生效）

以下 10 条原则贯穿所有开发活动，无需查阅文档即可执行：

1. **可维护性优先** — 宁可多花时间讨论方案，不要急于动手写代码
2. **单一职责** — 每个模块、文件、函数只负责一件事
3. **关注点分离** — UI 和业务逻辑分开，数据操作和展示分开，配置和实现分开
4. **先需求再设计** — 动手前先做需求分析，明确用户画像和功能优先级
5. **实体设计先于代码** — 数据库实体、字段、索引在编码前确定
6. **组件原子化** — 按原子设计方法论拆分组件，每个组件职责单一、可复用
7. **API 契约先行** — 接口定义先于实现，RESTful 规范和错误码统一维护
8. **测试金字塔** — 单元测试打底、集成测试覆盖关键路径、验收测试把关质量
9. **安全前置** — 认证授权、数据校验、错误处理在设计阶段就纳入
10. **AI 协作要给上下文** — 新对话开始时提供项目上下文，明确任务范围

## 关键约定速查

### 代码规范（详见 01）
- 使用 TypeScript，禁止纯 JavaScript
- 函数体不超过 30 行，嵌套不超过 3 层
- 文件不超过 300 行
- 禁止 `any` 类型
- 命名：组件 PascalCase，函数 camelCase，常量 UPPER_SNAKE_CASE

### 数据库规范（详见 02）
- 实体设计先于编码
- 每张表必须有 `id`、`created_at`、`updated_at`
- 外键用 `_id` 后缀
- 索引覆盖常用查询
- 使用 Schema 迁移管理变更

### API 规范（详见 03）
- RESTful 风格：GET/POST/PUT/PATCH/DELETE
- URL 小写，用连字符分隔
- 统一错误响应格式：`{ code, message, details }`
- 分页用 `page` + `page_size`
- 版本号放 URL：`/api/v1/...`

### 组件规范（详见 04）
- 原子设计五层：原子 → 分子 → 有机体 → 模板 → 页面
- 单一职责，props 不超过 7 个
- 容器组件和展示组件分离
- 组件注册表记录所有已有组件

### 测试规范（详见 07）
- 测试金字塔：单元 70% / 集成 20% / 验收 10%
- 命名：`描述（场景）- 预期结果`
- Mock 外部依赖，不 Mock 被测单元
- 关键路径必须有集成测试

### 安全规范（详见 08）
- 所有输入必须校验
- SQL 参数化，禁止拼接
- 敏感数据加密存储
- 密码/Token 禁止出现在日志
- CORS 白名单机制

### 部署规范（详见 10）
- 环境分层：开发 → 测试 → 预发 → 生产
- 12-Factor App 原则
- CI/CD 自动化
- 数据库迁移在部署前执行

## 如何使用本文档

1. **遇到开发决策时** → 先查"核心原则"，再查"任务路由表"找到对应文档
2. **不确定规范时** → 查"关键约定速查"获取快速答案，细节去读对应文档
3. **阶段交付时** → 查"开发阶段检查点"确认产出完整性
4. **需要深入理解时** → 直接 Read 对应编号的 `-mimo.md` 文件
