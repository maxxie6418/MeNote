## 一、为什么改

现状：Memo 视图与待办视图页头的「添加」按钮，点击后**把焦点送回左侧功能栏的快速录入框**并切档
（`focusComposer`，M07-01 入口二）。用户的反馈是这个跳转让人看不清"刚才点的添加到底去哪了"——
注意力被甩到左侧、当前视图没有任何直接的输入反馈。

需求（用户 2026-09-29）：**在 memo 和待办界面点「添加」时，不要跳转到左侧的快捷输入栏，要单独弹窗添加，给用户明确的反馈。**

并明确：后续要一个**内容输入窗口**，**只给非笔记类**添加内容；不同类型**复用同一套窗口结构、只换显示的设置**；
先做一个**通用、简单**的版本（即本稿）。

> 本改动**推翻**了 `wiki/Menote-功能拆解-v2.md` M07-01「入口二」与 `wiki/components.md` §6.2
> 「复用」行的既有定稿（"不另做输入框、切 mode 并聚焦"）。用户 2026-09-29 已授权**代码与这些定稿一起回写**。

## 二、窗口结构（通用，一个组件两种 kind）

```
AddEntryDialog (Modal 壳)
 ├─ 头：标题 = 「添加 Memo」/「添加待办」
 ├─ 输入区  textarea（打开即聚焦；Ctrl+Enter 发布）
 ├─ 模式附加项（同一位置、随 kind 换内容，高度不塌陷）
 │    ├─ kind=memo：正文含 `- [ ]` 时给「设为清单？」chip（可点开/关）
 │    └─ kind=task：截止 date + 优先级 高/中/低（与录入框「待办」档一致）
 └─ 底：「取消」(次) + 「发布」(主，空内容时禁用并给出原因)
```

- **字段与左侧录入框对应档位完全一致**（用户拍板），不缩水：待办 = 截止 + 优先级；
  Memo = 清单标记提示。复用 `Composer` 的 `ModeExtras` 与 `TASK_ITEM_PATTERN`，不复制第二份。
- **只有非笔记类**：kind ∈ {`memo`, `task`}。笔记仍走功能栏「新建笔记」/录入框「笔记」档，不进本窗口。

## 三、入口与行为

| 入口 | 现在 | 改后 |
|---|---|---|
| Memo 页头「添加 Memo」 | 跳录入框（memo 档） | 打开窗口（kind=memo） |
| 待办页头「添加待办」 | 跳录入框（task 档） | 打开窗口（kind=task） |
| Memo 时间轴 / 待办列表空状态出口 | 「切到录入框」 | 「添加 Memo」/「添加待办」，同样开窗口 |
| Memo 瀑布流空状态出口 | 「切到录入框」 | **改为「切回时间轴」**（见下） |

- **反馈**：发布后 → 关窗口 → 既有 toast（「已记录」/「已加入待办」）→ 新条目因 `publishMemo`
  `await refresh()` **即时出现在当前列表**。三重确认，不再有"点了没反应"的悬空感。
- **焦点**：打开时焦点落进输入区（可直接打字）；`Esc` 与点遮罩关闭（`Modal` 既有行为，`DESIGN.md` §6.4-5）。
- **瀑布流为何不加**：瀑布流只渲染**带图**的 Memo，文本 Memo 发布后**不出现**在网格里——
  在这一屏开窗口添加，用户会看到"加了却看不见"。故该空状态的出口改为**切回时间轴**
  （与它自己 hint「切回时间轴看全部 Memo」一致），到时间轴再添加。
- 功能栏的快速录入框**原样保留**，仍是添加内容的主入口；本窗口只是这两个视图「添加」的落地方式。

## 五、验收点

1. Memo / 待办页头点「添加」→ 弹出窗口，**不**再把焦点甩去左侧录入框。
2. 窗口内 Ctrl+Enter / 点「发布」→ 关窗口 + toast + 条目立刻出现在当前视图列表。
3. 待办窗口有截止 + 优先级；Memo 窗口写 `- [ ]` 时出现「设为清单？」。
4. 空内容时「发布」禁用且原因可见（`DESIGN.md` §6.1）。
5. 功能栏快速录入框行为**不变**（仍是主入口）。
