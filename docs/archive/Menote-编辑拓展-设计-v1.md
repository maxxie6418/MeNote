## 一、这份文档讨论什么

用户要求把编辑器相关能力当成一个系统来规划，而不是散落的四个小功能。系统内包括：

- 笔记正文的档位：即时编辑、只读、双栏兜底
- 样式：现代、统一；快捷改样式（工具栏或快捷键都可以）
- `@` 属性菜单（只在编辑态）
- Memo 与待办的编辑方式（同一套编辑器，形态像滴答清单：点开才编辑）
- 性能：编辑和切换不能卡
- 主题：最好能在后台编辑，而不是写死在代码里

不在本系统里、本文只登记边界的：

- 全局和弦（`Ctrl/Cmd+K/S/N`）。基础框架已经落地，见第十节。`@` 和 `/` 不是和弦。
- Markdown 批量导入、单篇导出、快照 ZIP。那是数据进出，不是编辑器。导出格式已在设计文档 §3.2 / §16.2 定过，属于 M5，不在这里另起一套。

## 二、已经对齐的方向

这些是这次对话里已经说清的，写进来避免下一轮又散掉。

1. 笔记正文不再追求四档各自长得一样。渲染出来的字只有一套：即时渲染的装饰。`markdown-it` 不再负责笔记正文。
2. 三档都挂在**同一个主编辑器**上。切换是改扩展和显隐，不卸载文档。
3. 双栏是兜底：左栏源码，右栏用**同一个**即时渲染、只读。右栏不走 `markdown-it`，也不要每敲一个字经 React 重渲染。
4. 只读是同一编辑器的一个状态：整篇保持渲染，不可改，光标行不翻回源码。界面上不叫「锁定」，那个词已经是隐私锁。
5. Memo 时间轴上收起的卡片继续轻量预览。只有展开的那一条挂编辑器。待办详情的描述区用同一个小编辑器。快速录入框和添加窗口仍是文本框。
6. `/` 只出样式。`@` 只出属性。工具栏渲染的就是 `/` 那张命令表，不另写一套按钮。
7. 编辑器看到的 Memo / 待办正文**没有** front matter。保存仍由现有的 `updateMemo` 把标签和任务字段写回去。

## 四、系统怎么切

一个编辑内核，三个宿主，两张命令表，一套主题。

```text
宿主
  笔记正文     三档：即时编辑 / 只读 / 双栏
  Memo 展开    只有即时编辑；Ctrl+Enter 收起，Esc 取消
  待办详情     描述区 = 同一个小编辑器；日期和优先级在编辑器外面

编辑内核（app/editor/，已有 CodeMirror）
  一个主 EditorView
  双栏时按需再挂一个只读 EditorView，离开只隐藏
  换笔记时两个一起换文档，不经 React 状态同步右栏

命令
  样式表  ←  / 菜单、浮动工具栏、固定工具栏、以后的 Mod+B
  属性表  ←  @ 菜单。笔记 / Memo / 待办各看各的项

主题
  令牌包。渲染装饰和源码栏字体都读它
  用户只选已发布的包，不写 CSS
```

宿主决定三件事，内核不管：

- 文档里有没有 front matter（笔记有，Memo / 待办没有）
- 保存策略（笔记自动保存；Memo / 待办 `Ctrl+Enter` 提交、`Esc` 放弃）
- 这一屏要不要档位切换（只有笔记正文要）

## 五、性能契约

这是完成标准，不是愿望。没量过不算做完。量法和 2026-09-28 即时渲染实测同一套：本地真实 Chrome，看主线程长任务，不看 devtools 的感觉。

| 动作 | 必须 | 禁止 |
|---|---|---|
| 即时编辑 ↔ 只读 | 同一个 `EditorView`。长任务小于 16ms | 卸载编辑器、切去 `markdown-it` |
| 再次进入双栏 | 右栏只是显示出来。长任务小于 16ms | 每次进入都 `new EditorView` |
| 第一次进入双栏 | 允许建第二个视图。普通笔记（小于 100KB）小于 50ms | 用 React `setState` 把全文推进右栏 |
| 打字（含双栏） | 右栏用 `EditorView.dispatch` 跟上。中文输入法组合期间不重算装饰（现有规则保留） | 每键跑 `markdown-it`；每键重渲染 `NoteWorkspace` |
| 换笔记 | 保持现有两阶段打开：先换屏，再读正文。列表高亮不跟着等正文 | 为了「复用编辑器」把 `selectedId` 提前抬起来（v0.5.3 量过，那样会从约 90ms 退到约 250ms） |
| Memo 时间轴 | 同时最多 **1** 个 `EditorView` | 每张卡片一个编辑器 |
| 换主题 | 换 CSS 变量，不重建文档 | 按主题拆一套组件 |

已有数字，当基线，不当新目标：视口装饰约 0.4–1.1ms / 4KB；800KB 文档敲一个字的无头测量中位约 26ms。双栏加上之后，打字成本相对「只有即时编辑」的增加量要单独量一次，超过 16ms 就停，不继续堆装饰。

切笔记的编辑器销毁（`key={itemId}`）这一轮**先保留**。上一轮的卡顿在等网络和整表刷新，不在 CodeMirror 构造。没有新的测量之前不做编辑器池。

## 六、笔记正文三档

| 档 | 主编辑器 | 右栏 | 光标行 |
|---|---|---|---|
| 即时编辑 | 即时渲染开 | 无 | 见源码（现有规则，失焦则整篇渲染） |
| 只读 | 即时渲染开，`readOnly` | 无 | 不翻回源码 |
| 双栏 | 即时渲染**关**（源码） | 只读即时渲染，文档由左边直接推 | 左栏就是源码 |

实现约束：

- 主编辑器在这三档之间不卸载。现在「双栏 / 仅预览」是另一截 React 树，会把编辑器拆掉。这是要改的结构，不是要调的样式。
- 右栏第一次需要时才创建，之后 `hidden`，换笔记或卸载正文区才销毁。
- 滚动同步在两个视图之间做，用 `requestAnimationFrame` 合并，不进 React 状态。
- 坏表格的「查看原文」今天强制切到仅编辑。仅编辑取消后，这条出路改为切到双栏（左栏就是源码），不再保留第四档。
- 设置里的四档开关，确认第 3 节第 1 条之后再改。在那之前，本文不要求改 `editor_modes`。

源码栏不要求看起来像渲染结果。要求的是：源码栏的字体、行距、代码块行号颜色，和渲染栏用同一组令牌，不要一边一套灰。

## 七、样式、工具栏、`/`

样式命令是一张表。每一条只有：id、标签、适用宿主、对文档做的那一次修改。`/`、浮动工具栏、固定工具栏、以后的键盘，都调用这一条，不各写一遍。

第一期命令，够用即可：

| 命令 | 文档上的结果 |
|---|---|
| 加粗 | 包 `**`，不是新语法 |
| 标题 | 行首 `#` 至 `###` 循环，或菜单里三档 |
| 行内代码 / 代码块 | 现有 Markdown |
| 无序列表 | 行首 `- ` |
| 四种命名颜色 | 封闭标记，两套消费方都能认。不用原始 HTML（`markdown-it` 禁止放行 HTML，分享页以后也要认） |

颜色的具体写法确认前不定死。约束先定：只能是命名颜色（沿用现有语义色，不引入自由色值），标记必须能被即时渲染和 `markdown-it` 各解析一次，导出的仍是纯 Markdown 文本。

代码块行号出现在**渲染结果**里（只读、双栏右栏、即时编辑里已经渲染的行）。源码栏保留编辑器自己的整篇行号，不在围栏里再画一列，避免两套行号叠在一起。

`/` 的触发：

- 只在编辑器里，行首或空白之后。
- 代码围栏内不触发。
- 输入法组合过程中不弹出。
- 不在搜索框、标题、设置里听 `/`。

工具栏：

- 设置三选一，记在本机，不进账号设置：浮动 / 固定 / 关。默认浮动。
- 浮动：有选区才出现，锚在选区旁。没有选区时不占地方。
- 固定：放在编辑区内部、正文头下面。正文头仍只有模式切换和更多菜单，这一条不变量不动。
- 同一时刻只有一种工具栏。`/` 在三种设置下都可用。
- Memo 展开编辑可以用浮动或 `/`，不放笔记那条档位切换，也不默认放固定条（卡片里没有那一行的高度）。

## 八、`@` 属性

`@` 是编辑态功能，不是全局快捷键。触发规则和 `/` 相同，但是另一张表。

菜单项用登记表：id、适用类型、默认开、设置里可关。写入走现有函数，不拼接 YAML。

| 类型 | 第一期项 | 写到哪里 |
|---|---|---|
| 笔记 | 存储路径 | 选已有文件夹，改 `folder_id`。路径从文件夹树现算，不写进正文 |
| Memo | 标签 | 保存时的 `menote.tags`，或正文里的 `#标签`（二选一，建议 YAML，和现在「编辑时看不见 YAML」一致：菜单改的是元数据，不是把围栏插进用户看见的正文） |
| 待办 | 优先级、日期 | 现有 `menote.task` 字段。编辑器文档里不出现这些键 |

还不是待办时，优先级和日期禁用，并说明原因。不假装能写。

设置只做开关，可选字段加默认值，不需要迁移。这一项确认后再改 `user_settings`。

## 九、Memo 和待办

目标是滴答清单那种「列表很轻，点开才编辑」，不是把笔记页的三档搬进每张卡片。

现在：

- Memo 展示是 `markdown-it`，编辑是裸文本框。YAML 由 `updateMemo` 在保存时重生，用户不该看见。
- 待办详情侧栏只有属性。正文要回 Memo 视图改。待办本身就是带任务字段的 Memo。

改成：

- 收起的卡片仍用轻量预览。时间轴上可以有很多条，不能各挂一个 CodeMirror。
- 展开的那一条换成编辑内核的即时编辑。传进去的是剥掉 front matter 的正文。
- `Ctrl+Enter` 保存并收起，`Esc` 放弃。这两条保持。`Ctrl+S` 已在快捷键框架里定义成「落盘并同步、不收起」，Memo 编辑会话接上之后就会这样，不另做一条保存路径。
- 待办详情的描述区用同一个组件。截止、优先级、状态留在编辑器外面的属性行。`@` 改这些字段时调用现有任务动作，不往正文里插 YAML。
- 可点的任务复选框是共享内核上的一个小部件：勾选改文档里的 `[ ]` / `[x]`。笔记和待办一起得到。不做假复选框（点了没反应是 `DESIGN.md` 禁止的）。这一项可以排在编辑器能稳定切换之后，不阻塞三档。

快速录入和添加窗口保持文本框。那里的发布仍是 `Ctrl+Enter`，不是 `Ctrl+S`。

## 十、和快捷键框架的接口

全局和弦的基础框架已经落地，不在本文重做：

- 登记表在 `app/shortcuts/`。一个捕获阶段监听。
- 已登记：`Ctrl/Cmd+K` 搜索，`Ctrl/Cmd+S` 落盘后同步或只同步，`Ctrl/Cmd+N` 打开 Memo 添加窗口。
- 编辑会话也是登记的：笔记正文控制器还在就算活跃；标题有未提交文字或正聚焦时算活跃；Memo 卡片处于编辑态时算活跃。`Ctrl/Cmd+S` 冲刷全部活跃会话，再 `runOnce()`。
- 以后的样式快捷键（例如加粗）如果是全局和弦，走 `registerShortcut`，动作调用第七节那张命令表。不要在编辑器里再挂一个 `document` 监听。

`@` 和 `/` 不进 `DESIGN.md` §6.3。它们是输入字符，不是和弦。

## 十一、分步

确认第三节之后再写实施计划。顺序按性能风险排，不按功能新鲜度排。

| 步 | 内容 | 完成看什么 |
|---|---|---|
| 1 | 笔记正文三档共用一个主编辑器；双栏右栏用只读即时渲染，文档不经 React | 第五节的切换和打字指标 |
| 2 | 样式命令表 + `/` + 浮动工具栏。加粗、标题、代码、列表、四种颜色、渲染态代码块行号 | 命令只有一份实现；预览卡片用的 `markdown-it` 能认出颜色标记 |
| 3 | Memo 展开编辑、待办描述区接同一个内核。正文不含 YAML | 时间轴同时只有一个编辑器；`Ctrl+Enter` / `Esc` 行为不变 |
| 4 | `@` 属性表。笔记选文件夹，Memo 标签，待办优先级和日期 | 不拼接 YAML；禁用项有可见原因 |
| 5 | 任务复选框小部件 | 勾选改的是文档，保存后派生字段跟着变 |
| 6 | 主题包：先内置一套。后台编辑界面单独排期，数据形状按第七节的封闭令牌 | 换主题不重建文档 |

固定工具栏、只读档的设置项，跟着第 1 步的档位一起做，不单开一步。

## 十三、明确不做

- 不换掉 CodeMirror，不引入块编辑器。
- 不删除 `markdown-it`。收起的卡片和分享页还要用。
- 不让用户写 CSS，不让用户自定义色值。
- 不在搜索框、标题、设置里弹出 `@` 或 `/`。
- 不把存储路径写成正文里的新字段。
- 不在这一系统里做批量导入、快照 ZIP、备份恢复。
- 不把待办详情里没有的「子清单」「活动记录」编出来。模型里没有。
