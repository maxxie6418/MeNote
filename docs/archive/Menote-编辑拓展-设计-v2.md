## 一、只认这四条

上一稿把对话里的临时取舍写成了定论，和这四条混在一起，会挡最优方案。那些取舍作废。下面四条是需求，方案都从这里推。

1. **输入要统筹。** Memo、待办、笔记的快捷输入，以及笔记正文编辑，尽量功能一致、体验一致、切换和输入都流畅。笔记可以分成「快捷录入」和「正文编辑」两块；如果一块引擎无法同时保住性能和功能，允许拆开做，但命令、主题、样式语义仍然是一套。搜索框除外：只要纯文本，不要属性，不要 `/`。
2. **正文编辑不能卡。** 打字、编辑/预览/即时渲染之间的切换、文章之间的切换，都不能卡。反复操作之后也不能变卡（实例、监听、装饰不能越积越多）。
3. **看起来要是一件东西。** 编辑态和预览态风格尽量一致。视觉要干净。最好能在后台配置主题，用来调整各类样式，而不是把样式写死。程度是「可调的主题」，不是用户自己写 CSS。
4. **编辑能力要够。** Markdown 本身继续能表达样式。除此之外，`@` 创建属性，`/` 创建样式。两种命令要覆盖各个内容输入场景，不单给笔记正文。

可以换掉现有编辑框架。可以推翻四档编辑模式的现实现。生产环境里正在用的编辑器，在试验证明可用之前不动。

## 二、要覆盖的场景

先把现在会打字的地方列全。试验页要能代表它们，不代表就要在第一天改生产代码。

| 场景 | 现在是什么 | 本系统 | 说明 |
|---|---|---|---|
| 功能栏快捷录入 | 文本框，Memo / 待办 / 笔记三档 | 快捷宿主 | 笔记档是快捷录入，不是正文编辑器 |
| 添加内容窗口 | 文本框，Memo / 待办 | 快捷宿主 | 与功能栏同一套字段和命令 |
| Memo 时间轴原位编辑 | 文本框，保存时才写回 YAML | 快捷宿主 | 用户仍不该手改 YAML |
| 待办详情里的描述 | 现在不能编辑，得回 Memo | 快捷宿主 | 和 Memo 是同一条内容 |
| 笔记正文 | CodeMirror，四档 | 正文宿主 | 长文、切模式、切文章都在这里考 |
| 笔记标题 | 单行输入 | 排除 | 不是正文，也不需要 `@` / `/` |
| 搜索框 | 单行输入 | 排除 | 需求已排除 |
| 表格网格 | 另一套结构化编辑器 | 排除 | 单元格不是这篇 Markdown 的编辑器；以后若要 `@`，另开，不塞进这一轮 |

快捷宿主可以同时存在多个（录入框、弹窗、一张展开的 Memo）。正文宿主同一时刻只有一篇。这是性能上最重要的差别，也是允许拆引擎的原因。

## 三、系统只定接口，不定死引擎

生产代码今天是：快捷处用文本框，正文用 CodeMirror，预览用另一套 `markdown-it`。这能解释「编辑和预览不像」「快捷处没有 `@` `/`」。它不是必须保留的结构。

新系统分成三层。上层两层无论引擎换不换都不变。

```text
宿主
  快捷宿主    短文本。可以有多个。命令按类型过滤
  正文宿主    长文。同时一篇。有编辑 / 预览 / 即时渲染，以及现有的双栏是否保留由试验决定

共享层（必须只有一份）
  样式命令    / 与工具栏调用这一份
  属性命令    @ 调用这一份，按类型过滤
  主题包      编辑态和预览态读同一份令牌
  样式语义    加粗、标题、代码块、颜色在两种状态下指同一件事

引擎（允许两套，也允许以后换掉）
  由试验页量完再定。第一版试验可以用现有 CodeMirror 当正文引擎、轻量编辑器当快捷引擎
  宿主不直接依赖某个引擎的类型
```

宿主接口要小，这样换引擎不用改 Memo 页和笔记页：

- 读当前文本、写入一次修改、报告焦点是否在内容里
- 接收主题包
- 接收当前类型（笔记快捷 / Memo / 待办 / 笔记正文），用来过滤 `@` 菜单
- 正文宿主额外接收视图档位，并在切档、切文章时不把未销毁的实例留下来

`@` 和 `/` 是输入字符触发的菜单，不是全局快捷键。全局的 `Ctrl/Cmd+S` 等已经有登记表，本文不重做那一层。样式如果以后要键盘（例如加粗），动作仍调用样式命令这一份，不各写一遍。

## 四、试验页

这是第一件要做的事。不先改正在部署的编辑器。

位置：设置里新增一页「编辑试验」。不作为打开设置时的默认页。页顶用可见文字写明：这里的内容不写入笔记、不上传、不影响现有编辑器。

已确认的隔离（2026-09-29）：页上固定三篇样文，存在本机钥匙 `menote:editor-lab:v1`。不进笔记库、不同步、不进搜索。刷新后还在，以便来回切；「恢复样文」清回初始三篇。

性能读数只留能对上原因的：动作开始到下一帧的毫秒数，以及浏览器报出的长任务（超过约 50ms 的主线程阻塞）是否紧跟在刚才那个动作后面。对不上就不编原因。内存和帧率曲线不记。

页上两块，对应两个宿主：

1. **快捷输入。** 三个框：Memo、待办、笔记快捷录入。同一组件，只换类型。能打字，能出 `@` 和 `/`。不调用现有的发布接口。
2. **正文。** 一个正文框，旁边能切编辑 / 预览 / 即时渲染。若试验发现双栏仍有必要，再加一档，不在开页时就定死。下面有三篇固定样文，用来来回切换。样文含标题、粗体、代码块、一段较长文字，方便看卡顿和风格差。

页上另有一块读数，给第 2 条需求用，不靠感觉：

- 最近一次打字、切模式、切文章花了多少毫秒
- 当前编辑器实例数、登记的监听数
- 连续切换 20 次之后这两个数是否还回去

主题在这一页用一份本地主题包试调（颜色、标题字号、代码块底色这一类）。包的形状跟以后后台要存的一样。后台编辑界面不在试验页的第一刀里做，但没有这个形状，后面的后台没处接。

试验页的通过线（没到就不许替换生产编辑器）：

| 项 | 线 |
|---|---|
| 打字 | 普通样文上不出现超过 50ms 的长任务；中文输入不丢字 |
| 切模式 | 单次低于 50ms；来回 20 次后实例数和监听数回到切换前 |
| 切文章 | 样文已在内存时单次低于 100ms；来回 20 次后实例数不增加 |
| 快捷框 | 三个框都能用 `@` 和 `/`；反复聚焦不会多挂监听 |
| 风格 | 同一段文字在编辑态和预览态的标题、粗体、代码块、颜色用的是同一组令牌。允许源码标记在编辑态可见，不允许两套互不相干的字号和颜色 |
| 隔离 | 试验页不写本地笔记库，不调用同步 |

这些数字是验收线，不是已经测过的结果。第一轮量完若线设得不合理，改线，不改「不能卡」这条需求。

## 五、命令与主题（两层宿主共用）

### `@` 属性

在快捷宿主和正文宿主里，`@` 出现在行首或空白后才打开。代码块内不打开。搜索框、标题框不听 `@`。输入法组合过程中不打开。

菜单内容按类型过滤，设置里可关单项。第一期够用的项：

| 类型 | 项 | 落点 |
|---|---|---|
| 笔记正文、笔记快捷录入 | 存储路径 | 选文件夹。快捷录入是「发布到这个文件夹」，正文是「移动当前篇」。都不把路径字符串写进 Markdown |
| Memo | 标签 | 写入条目的标签字段，不把 YAML 围栏暴露给用户 |
| 待办 | 优先级、日期 | 写入现有任务字段。还不是待办时该项禁用，并写明原因 |

以后加项只加登记，不加一种新菜单。

### `/` 样式

`/` 的触发规则与 `@` 相同，菜单是另一张表。第一期：加粗、标题、列表、行内代码、代码块、少量命名颜色。工具栏如果要做，按钮调用这张表，不另写插入逻辑。浮动还是固定，放到试验页里并排试，不在本文先定一种。

颜色不用原始 HTML。用一小段封闭标记，编辑态和预览态都能认。具体写法在试验页定，定之前不进生产渲染器。

Markdown 源码仍然是样式的一种写法。`/` 是同一效果的入口，不是第二套文档格式。

### 主题

主题是一份命名令牌：标题各级、正文、粗体、引用、链接、代码块底色、行号、少量命名颜色。编辑态和预览态只读这份。

- 用户不写 CSS，也不填任意色值。
- 后台（实例拥有者）编辑并发布主题包。用户在设置里选已发布的包。这是第 3 条的目标形态。
- 试验页先用本地的同一份结构，避免为了配色去等实例管理。后台页面在试验页的风格线通过之后再做。
- 令牌只能覆盖已有语义，不能改布局尺寸。布局仍以 `DESIGN.md` 为准。改 `DESIGN.md` 要另得确认。

## 六、什么时候动生产代码

顺序固定。跳步会把未验证的编辑器送到正在用的站点上。

| 步 | 做什么 | 不动什么 |
|---|---|---|
| 1 | 设置里的试验页：两个宿主、样文、读数、本地主题包。引擎可以先包一层现有 CodeMirror，也可以同时放一个更轻的快捷引擎 | 笔记页、Memo 页、录入框、添加窗口 |
| 2 | 在试验页接上 `@`、`/` 和主题切换，按第四节的线量 | 生产渲染器 |
| 3 | 根据读数决定：快捷和正文是否分引擎；预览用同一引擎还是共享令牌的第二渲染器；四档里留哪几档 | `wiki/` |
| 4 | 一次只换一个生产场景，从快捷录入或添加窗口开始，正文最后换 | 未通过的场景保持原样 |

第 3 步之前，不讨论「必须留下双栏」或「必须删掉 markdown-it」。那是测量结果，不是需求。

换生产场景时才需要改 `wiki/` 和 `DESIGN.md`。试验页本身不改变已定稿的编辑器行为，只增加一个标明试验的设置页。加这个页之前，仍要在实现计划里写明导航上多一项，避免当成无声的默认页。

## 七、明确不做

- 不在试验通过前替换正在部署的编辑器。
- 不给搜索框和笔记标题加 `@` 或 `/`。
- 不把这一轮扩成表格单元格编辑器、批量导入或快照导出。
- 不让用户编写 CSS。
- 不把 v1 里的三档方案、右栏实现、Memo 是否挂 CodeMirror，当作本文的前提。
