## 五、偏离与实现选择（24 处，均已在对应文档或代码注释登记）

1. **版本历史用"主操作区独立面板页"**（界面稿默认取舍已采纳）：理由是弹窗最大宽 400px 装不下并排 diff，而给 `DESIGN.md` 加"宽弹窗"档属改视觉源。
2. **保留密度只读**：设置页只开放条数与最长时长，密度按定稿规则展示。
3. **「标记为保留」可取消**（界面稿默认取舍）。
4. **永久删除确认框不提"快照文件"**：正文只写"条目 + 全部版本 + 不再被引用的附件"与"不可撤销"。
5. **正文里的附件引用写法由本程定稿**：图片 `![名](/api/attachments/h/<sha>)`、非图片 `[名](…)`——预览不用自定义语法、客户端一条正则抓全引用、缩略图只是渲染时加 `?thumb=1`。
6. **缩略图在浏览器生成**（设计 §十-1 的默认）：否决架构 §八 的 `media.worker`。
7. **附件管理页留 M6**（设计 §十-2 的默认）：M4 只做接口 + 元数据 + Cron。
8. **`StorageEnv` 收窄**：服务层只依赖 `DB` + `ATTACHMENTS`，不拿整个 `EnvBindings`。
9. **表格的一处退化**：**主动降级**（「降级为普通笔记」）——确认框已按界面稿写全三段，但**按钮禁用并写明原因**：它要把 `items.type` 从 table 改成 note，而 `ItemMetaPatchSchema` **不允许改 type**（属接口变更，见 §七-11）。此前登记的另两处已在收口期间补齐：**标签列 chip 编辑**（v0.4.30，存储仍是逗号分隔字符串）与**行拖动排序**（v0.4.30，键盘等价入口是行菜单的上移/下移）；**"自动降级提示条"**在 v0.4.26 补上。
10. **附件引用只在"上传时"上报**（`finalize(itemId)`）；**编辑后再对齐引用**需要条目保存携带引用集合（要改 items API 请求结构），留 M6 与附件管理页一起做；期间由**孤儿 30 天规则**兜底。
11. **`wrangler.jsonc` 的 `r2_buckets` 与 `triggers.crons`**：用户 2026-09-27 确认 R2 后落地；绑定名统一为 `ATTACHMENTS`。
12. **新增 `fnbarWiring`**（从 `App.tsx` 抽出）：把"从独立页回笔记区"这条规则收成一处，App 已顶到 500 行预算。
13. **回收站列出文件夹**（v0.4.28 补）：界面稿 §6.5 要求文件夹也出现在回收站里；实现为"条目 + 文件夹"两张查询在模型层合成一张列表，恢复按 kind 分流（文件夹走 `restoreFolder`）。同批登记一条遗留：**文件夹的永久删除服务端还不支持**（见 §七-12）。
14. **两条审计手段**（见 §八）：调用点检查（非测试的调用点为零即未接线）与端到端可达性（从 `main.tsx` 沿静态 + 动态 import 递归），以及"服务端端点逐个查测试覆盖"。这是被 M4 期间四次"写好了没接上"逼出来的。
15. **封存原因（`reason`）只有三种会有代码产生**（2026-09-27 文档承诺审计）：设计 §4.1 列了 7 种，实现里**只有 `autosave_idle`（Cron idle 兜底）、`manual`（手动存为版本）、`pre_restore`（恢复前封存）**会真的落库；`session` / `pre_conflict` / `pre_mcp` / `pre_convert` **没有任何生产点**。各自的归属：`pre_mcp` 属 M6（MCP 修改前）；`pre_convert` 与本轮 §七-11 的"主动降级"绑在一起（降级还没落地，自然没有降级前封存）；`session` 需要一个"另一台设备改过 / 距上次编辑 > 1 小时"的判定（`items.last_device` 已在 v0.4.32 接上，但**封存接口还不能表达非 manual 的原因**，见 §七-13）；`pre_conflict` 与 M2 的冲突副本路径相关（现在生成副本时没有封存）。**类型与中文映射都在**（`VERSION_REASON_LABELS` 七条齐全），缺的是生产点——所以界面上不会出现"未知原因"。
16. **共享包的重复常量已合并**（2026-09-27）：`content.ts` 曾有 `VERSIONS_MIN/MAX`（**零消费方**）、`settings.ts` 又有 `VERSIONS_KEEP_MIN/MAX`——同一件事两套名字。现在只留一份（定义在 `content.ts`，`settings.ts` 导入并转出，契约校验与设置页同源）。同批核对：`content.ts` 的 **23 个常量现在全部有消费方**。
17. **表格条目不再显示两个"点了没用"的控件**（v0.4.35）：①编辑模式切换（表格分支不看 `mode`，它有自己的"表格 / 图册"档位）；②「添加附件」（附件的占位与落库都要插进 Markdown 正文，表格没有 `EditorHandle`——文件会传上去却无人引用，30 天后按孤儿清掉）。依据是界面稿 §3 的表格正文头只列了标题 + 锁标识 + 更多菜单。**这一类"界面里有但没作用"的构件**已并入 §8.2 的审计清单（查"控件对当前条目类型是否真的有作用"）。
18. **设置的乐观更新补齐失败路径**（v0.4.36）：`patch` 先改界面再落盘，唯一调用方是 `void userSettings.patch(...)` → 写盘失败（存储配额满 / IndexedDB 被禁用）时 rejection 被吞、**界面停在"已生效"的假象**。现在失败**回滚 + 报 toast**、且不触发 `onWrite`；同批删掉"设了从不复位也没有消费方"的 `setPending(true)`，并把**没有调用点**的 `userSettings.reload` 接到同步后的 `refreshAll`（否则别的设备改了设置，本机界面一直显示旧值）。**审计教训**：`void action(...)` 是本仓库刻意的写法，脚本报"73 处没有 `.catch`"**不构成结论**——要问"这些动作自己有没有兜错"。
19. **附件队列兜住依赖项抛错**（v0.4.37）：`uploadAttachment` 契约上不抛错，但依赖项（哈希 / 网络 / 元数据落库）可能抛，而 `queue.run()` 没兜、调用方是 `void attachments.add(files)` → 任务**永远停在 `uploading`**（状态栏一直"正在上传 N / M"）、正文占位符**永久残留**。现在异常降级成普通 `failed`（原因可见 + 可重试，占位保留）。
20. **隐私设置页两个并列主色按钮**（v0.4.39，**唯一一处违 `DESIGN.md` §5.1**）：点「启用隐私锁」展开启用表后，卡片里的入口与表单里的「启用」**同时**是实心主色按钮（界面稿 §四① 只要一个主按钮）。修法：表单展开时**收起入口**（表单自带「取消」，用户不会没有退路）。同批把"每区域最多一个主操作"做成**渲染层断言** `assertSinglePrimaryAction(region)`（按区域而非整页）并铺到 8 屏，其余屏全绿。
21. **四处输入框把键盘焦点环抹掉了**（v0.4.41，违 `DESIGN.md` 禁止项 #11）：`.searchbox input` / `.docpane__title-input` / `.tagchips__input`（M4 新加）/ `.tree__input` 都写了 `outline: none` 且**没有补偿样式**——特异性高于或等于全局 `:focus-visible` 又写在它之后，于是**键盘用户看不见焦点在哪**。修法：四处删掉 `outline: none`（全局 `:focus-visible` 只在键盘聚焦时出现，鼠标点击不会多画外框）；保留的两处（`.composer__input` / `.field__input`）各有补偿样式。新增**白名单式守卫**（`helpers/focus.ts`）：白名单每条必须写清补偿理由、**过期条目会被报出来**。

### 8.1 为什么加这一步

| # | 发现 | 后果 | 修复 |
|---|---|---|---|
| 1 | `routes/versions.ts` **没挂载**到 `index.ts` | 版本历史的五个端点在线上全 404（单测直接打服务层，所以没暴露） | v0.4.19 |

### 8.2 两个审计手段（可复跑）

1. **调用点检查**：对每个"声称做完"的构件，在源码里找**非测试的调用点**。
   零调用点 = 未接线。还要顺带看"被引用了但从未被调用"的死导出（第 3 次那 4 个死函数就是这么发现的）。
2. **端到端可达性**：从 `apps/web/src/main.tsx` 出发，沿**静态 import 与动态 `import()`** 递归解析，
   得到"运行时真能加载到的模块集合"，再核验关键模块是否在其中。比"有引用方"更强——
   能抓出"被引用了、但那条分支永远不成立"。
   脚本是**只读的、放在仓库外**（不往仓库里塞工具文件），一次跑完 24 个候选模块。
3. **服务端端点覆盖**：把路由里声明的端点逐个拎出来，查测试目录里有没有真调用它的用例（本程：17/17 覆盖）。
4. **渲染层断言**（v0.4.38 新增，已抽成 `apps/web/test/helpers/a11y.ts`、铺到 **8 屏**）：**不扫源码，直接渲染**再查不变量——例如"每个 `button` / 输入控件都有可访问名字"（`placeholder` **不算**名字），并要求控件数下限，避免"零个控件也算通过"。写这条是因为**源码级扫描被自证证伪过**：扫 `<button>` 的脚本把 `onClick={() => undefined}` 里的 `=>` 当成标签结束，于是坏例也不报；改好后扫出的唯一一处又是误报（名字来自 `{entry.title}` 表达式）。**能渲染的断言就不要靠字符串匹配。** helper 自带常驻自证用例（坏例必须被拒、好例不误报、下限真的起作用）。

> **审计工具的三次翻车（都记在案）**：①`Select-String -List` 只返回首个匹配 → 把已接好的文件判成没接；②多根目录 + `-Include` 漏文件 → 一度误判 `privacyExcludeSql` 无人使用（差点写成"隐私内容可能泄漏到搜索"）；③扫 `<button>` 的正则被 `=>` 搞乱 → 假"0 处"。**规矩**：下"没人用 / 没接上 / 全部合规"这类结论前，先造**已知坏例与已知好例**喂给工具自证；自证不过就换方法（优先渲染层断言）。

5. **已有守卫的"覆盖面"也是审计对象**（v0.4.40 新增）：`DESIGN.md` §3.2-1「一切颜色走令牌…没有例外」**本来就有守卫**，但它只扫 `app.css`、只认 `#hex` 与 `rgb(`——`hsl(` 与**颜色关键字**会被静默放过（"扫不到"的漏洞）。**教训**：审计不只问"有没有守卫"，还要问"**守卫认哪几种写法、扫哪些文件**"；发现缺口就把守卫补强，并给守卫本身写自证用例。

### 8.4 "哑数据"审计（2026-09-27 第三轮）

同一天做的第三类审计：找**写了但没人读 / 读了但没人写**的字段与函数（"哑数据"）。产出三条：

| # | 哑数据 | 后果 | 处置 |
|---|---|---|---|
| 1 | **`items.last_device`**：服务端支持 `X-Menote-Device` 并写入该列，但头名只在 Worker 里定义、**客户端从没发过** | 该列永远是 null → 需求 §12.2-3 的"**另一台设备改过**"（M11-01 的 `session` 封存触发）无从判断 | **v0.4.32 已修**：头名提到共享包、客户端随正文保存上报（4 例） |
| 2 | **`items.sealed_rev`**：全仓**无人写入**（只出现在 DDL / 类型 / 同步载荷里） | 功能上无影响（封存去重实际走 `content_hash`），但**列名会误导后来人**以为"封存过哪一版"有记录 | **登记在案**：要么在封存时写上它（`sealVersion` 更新 `sealed_rev = rev`），要么在数据模型文档里注明"预留、暂未使用"。倾向后者（真源是 `content_hash`，双份记录迟早不一致） |
| 3 | **`listUnfinishedAttachments` / `countUnfinishedAttachments` 零调用** | 界面稿 §7.2 要求"上传中离开页面，**回来时从状态栏/清单条上能看到未完成项**"——当时队列只在内存里，**刷新即丢**，回来时看不到 | **v0.4.33 已修**：`useAttachments` 切条目时读一次本地未完成附件（纯读、与实时队列分开统计），状态栏显示"有 N 个附件没传完"（警告态）。**边界如实写清**：只能看到、**不能自动续传**（文件已不在手上），续传靠重新选一次文件（命中哈希即秒传），所以不给一个点了没用的「重试」按钮 |

> 三条的共同教训与 §8.1 一致：**光看"有没有这个字段"不够，要看"谁读它、谁写它"**。
> 一个字段只在类型与 DDL 里出现，多半意味着"设计打算这么做、实现没接上"。

### 8.3 本程审计结论

- 前端：**24/24 关键模块可达**（从 `main.tsx` 可达 135 个模块），四个 feature 下**无孤儿模块**；
- 服务端：**17/17 M4 端点有用例走过**；`routes/*` 全部挂载；
- **扩展审计（2026-09-27，覆盖 M1–M4）**：自动发现 `apps/web/src` 下**全部 144 个源码文件**逐个查可达性——
  **144/144 可达、0 个孤儿文件**；再对 82 个 `.tsx` 里导出的**大写标识符**（组件惯例）查"别处有没有当
  JSX / 工厂用"——只有 **4 个**只在**本文件**或**测试**里用（`COMPOSER_MODES` / `AUTO_LOCK_NOTICE_MS` /
  `EMPTY_SEARCH_STATE` / `TrashRetentionChip`），**没有"写了但从没渲染"的组件**。
  （`EMPTY_SEARCH_STATE` 是给测试用的导出；`TrashRetentionChip` 原本确实是死件，本轮已在回收站页头用上。）
- 同轮借审计发现并修掉一处**"接上了但接错"**：回收站页头把保留期写死成"30 天"、且 `useTrash` 算剩余天数
  时用的是默认值——**用户在设置里改成 7 天后，文案与倒计时都不跟着变**。现在保留天数从
  `user_settings.version_trash.trash_retention_days` 一路传到页头与剩余天数计算。
- **给后续里程碑的规矩**：声称某个前端构件做完时，必须能贴出它的调用点（grep 得到），
  否则一律记为未完成；收口前跑一遍 8.2 的三步。
