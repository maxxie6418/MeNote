## 一、这一屏是什么

**入口**：设置 › **MCP**（导航第 11 类，排在「分享」与「数据管理」之间——功能拆解 M18-01 的定稿顺序；`router.ts` 的 `SETTINGS_PAGES` 现在 10 类，本批补齐成 11 类）。

**页头**（`PAGE_META`）：

```ts
mcp: { title: "MCP", summary: "让 AI 工具读写你的内容：地址、令牌与调用记录" }
```

**它解决什么**：用户不需要碰命令行就能建一枚令牌、拿到 MCP 地址、把它交给 Cursor / Claude Code / Codex，然后在这里看这枚令牌都被用来做了什么。

**这一屏的四块**（照功能拆解 M17-01 的操作清单拆）：

| 块 | 内容 | 依据 |
|---|---|---|
| A | MCP 地址 + 接入说明 | M17-01「设置页同时显示 MCP 地址和一段接入说明【补全】」 |
| B | 令牌列表（主操作：创建令牌） | M17-01「列表显示：名称、前缀、权限、范围、过期时间、最近使用时间、状态」 |
| C | 创建令牌弹窗（含**一次性**完整令牌） | M17-01「创建后完整令牌只显示一次，提供复制」 |
| D | 令牌审计弹窗（该令牌的写操作记录） | M17-02「令牌详情页查看该令牌的写操作记录（工具、条目、结果、时间）」 |

## 二、块 A：地址与接入说明

```
┌─ setcard ────────────────────────────────────────────────┐
│ 接入                                        ⓘ           │
│ ┌─ setrow ─────────────────────────────────────────────┐ │
│ │ 地址  │ https://<当前站点>/mcp        [复制]        │ │
│ └──────────────────────────────────────────────────────┘ │
│                                        [ 接入说明 ]      │
└──────────────────────────────────────────────────────────┘
```

- **地址**：`window.location.origin + "/mcp"`，**不新增接口**（前端本来就知道自己的 origin）。用链接样式 `.sharelink`（DESIGN.md §5.3：文字链接走 `.link` / `--primary-ink`，不用按钮冒充链接）。
- **地址必须可见**（不是能力说明，是用户要拿去填的东西）。**复制**是次操作按钮。
- **ⓘ（`InfoHint`）**：MCP 地址是固定的；令牌决定它能读到什么。`POST /mcp` 是无状态端点，不支持 SSE。
- **「接入说明」**是次操作按钮，点开一个 `Modal`（§5.3：需要阅读的 → 弹窗；菜单用于锚定在元素旁的短选项，这里是"读一段东西"）。弹窗里 3 步 + 一段可复制的配置示例（**代码块用等宽字体，不加第二套视觉**）。

**为什么不把接入说明平铺在页面上**：§5.4-1「界面辅助文案默认不写」。它是"用法说明"，用户 90% 的时间不需要它。但它又是 M17-01 明确【补全】要求给的——所以给成一个**按需展开的弹窗**，而不是一屏常驻的灰字。

## 三、块 B：令牌列表

### 3.1 一行显示什么

**照 M17-01 的七项，一行里全给，不藏进"详情"**（这一屏的行不多，一行一行看比点开更省事）：

```
┌─ setcard ──────────────────────────────────────────────────────┐
│ 公司电脑的 Cursor                          mn_3fK2…   3 / 20  │
│ 只读 · 新建和追加 · 全部内容 · 含 Memo · 永不过期              │
│ 最近使用 2 小时前 · 30 天后过期                                │
│                                        [ 审计记录 ] [ 撤销 ] │
└───────────────────────────────────────────────────────────────┘
```

| 位置 | 内容 | 口径 |
|---|---|---|
| 第一行左 | **名称** | 用户自己起的，如「公司电脑的 Cursor」 |
| 第一行右 | **前缀** `mn_3fK2…` + **实时计数** `3 / 20` | 计数必须可见（§5.4-2「实时计数」） |
| 第二行 | **权限**：只读 + 勾了的位（`MCP_PERM_LABELS` 那四个中文名，`·` 分隔） | 没勾的位**不列**（不写"未授予修改和移动"这种否定式） |
| 第二行 | **范围**：`全部内容` / `3 个文件夹` / `1 个文件夹` | 范围收窄时给数量，不在这里铺文件夹名（太长） |
| 第二行 | Memo：`含 Memo` / 不含 Memo（不写） | |
| 第三行 | **过期**：`永不过期` / `30 天后过期` / `已过期` | 相对表述，与既有 `formatExpiry` 同一口径 |
| 第三行 | **最近使用**：`最近使用 2 小时前` / `还没用过` | |
| 第三行 | **状态**：`生效中` / `已撤销` / `已过期` | 用 `Pill` 状态胶囊（§5.3：顶栏状态用 `pill`；这里是行内状态，同一控件）。**已撤销 / 已过期**的行整体降透明度，但**仍可展开审计**（审计是判断"该不该撤销"和"撤销后有没有还在用"的依据，撤掉了就看不到了） |
| 按钮 | `审计记录`（次操作）/ `撤销`（次操作） | |

**已撤销 / 已过期的行**：不再提供 `撤销`（没意义），只留 `审计记录`。**`keep` 语义**：不物理删，所以历史要能查。

### 3.2 主操作与上限

- **主操作**：`创建令牌`（`variant="primary"`，`size="sm"`）。**同一屏只有这一个实心主色按钮**（§5.1）。
- **达上限时**（有效令牌 20 个）：按钮**置灰 + 旁注平铺**「已达 20 个上限，撤销一个后才能新建」（§6.1：禁用必须说明为何禁用，**不可只置灰**、不可只靠悬停）。

### 3.3 撤销的二次确认

**沿用 `MySharesPage` 的行内二次确认**（`pendingRevoke` → 「确认撤销 / 取消」），不弹 `ConfirmDialog`——理由：行内确认时**上下文就在眼前**（用户看着是哪一枚令牌），而弹窗确认框里要重新描述对象。

后果**平铺**一行（§5.4-2：破坏性后果必须可见，不藏进 `InfoHint`）：

> 撤销后这枚令牌立刻失效，还在用它的 agent 会开始报错。**无法恢复**——需要重新建一枚。

用 `variant="danger"`（§5.1 危险操作：危险色文字 + 危险色描边）。

## 四、块 C：创建令牌弹窗

**形态**：`Modal`，两个态——**填写态** → **已创建态**（原地切换，不跳页）。

### 4.1 填写态

字段顺序按"从必到选"，必填在前：

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 名称 | `Field`（单行输入，`maxlength=64`） | ✅ | 占位「如：公司电脑的 Cursor」 |
| 权限 | 三个 `role="switch"` + `.toggle`（**一档一个开关**，§5.3「可并存 → 开关组」） | — | 见下 |
| 范围 | 盒式 `SegmentedControl` 两档：**全部内容** / **指定文件夹** | — | 选「指定文件夹」时下方展开缩进的复选列表 |
| （范围细项） | 复选框列表（depth 1 顶格、depth 2 缩进一格） | — | 勾一个文件夹**自动含它的子文件夹**（需求 §4.5 最多两层），所以**只列顶层，勾选即含子** |
| 包含 Memo | `role="switch"` + `.toggle` | — | 默认**关**（M17-03「默认不勾选＝不可见」） |
| 有效期 | 盒式 `SegmentedControl`：`7 天` / `30 天` / `90 天` / `自定义` / `永不过期`，默认 `30 天` | — | 选「自定义」时展开 `<input type="date">`（与 `MySharesPage` 同一手法） |
| 允许通过 URL 使用 | `role="switch"` + `.toggle`，默认**关** | — | 勾选时**下方平铺风险说明**（§5.4-2 警告必须可见） |

**权限那一组的呈现**（关键）：

```
权限
  ✓ 只读                          ← 不可取消，写成一行可见文字，不用置灰开关
  [开关] 新建和追加
  [开关] 修改和移动
  [开关] 移到回收站
```

- **「只读」不用置灰开关**：置灰还得解释为什么（§6.1），而它压根不是一个选项——写成一行「只读（始终包含）」+ 一个常开的勾选图形即可。**三个可勾选项默认全关**（勾哪个给哪个，与定稿「三个级别相互独立勾选」一致）。
- **ⓘ 里的口径**：「只读之外的三个级别互相独立。比如只勾『新建和追加』，那个 agent 就能往 Menote 里记东西，但改不了、也删不掉已有的条目。」

**「允许通过 URL 使用」的风险说明（勾选时可见，措辞照定稿 §17.2 的三点）**：

> 令牌放进 URL 后会出现在各种日志里：Cloudflare 与 Workers 的请求日志、客户端自己的日志、代理服务器日志。URL 也容易被截图、粘进聊天或提交到代码仓库。**建议这类令牌只给只读权限，并设较短的过期时间。**

### 4.2 已创建态（一次性令牌）

创建成功后弹窗**原地切换**：

```
┌ 创建令牌 ───────────────────────────────┐
│ 令牌已创建                              │
│ ┌─────────────────────────────────────┐ │
│ │ mn_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX  │ │  ← 只读 input，可全选
│ └─────────────────────────────────────┘ │
│ ⚠ 这是唯一一次显示完整令牌。关闭后无法再查看，│
│   只能看到前缀。                        │
│                     [ 复制 ]  [ 我已保存 ] │
└────────────────────────────────────────┘
```

- **完整串用只读 input 而不是一段文字**：能被全选、用户自己也能手动拷。
- **「只显示一次」的后果必须平铺可见**（§5.4-2），且**重复一次**（正文一行 + 一次 `InfoHint` 也可以，但这里只有一句、不要两层）。
- **「复制」是主操作**（这一态唯一的推进动作），「我已保存」是次操作。**两个按钮里只有一个实心主色**（§5.1）。
- 关闭弹窗即丢弃。**不做"关闭前再确认一次"**——它不是破坏性操作，只是读不到而已；加一道确认只会让人烦。
- 复制失败沿用 `MySharesPage` 的做法：`pushToast(完整串, "info", { label: "复制失败，请手动复制" })`——**兜底也要给得出来**（剪贴板 API 在非 https 下会失败）。

## 五、块 D：审计记录

- **入口**：令牌行上的 `审计记录` 次操作按钮 → `Modal`。
- **为什么用弹窗而不是侧滑详情**：DESIGN.md §6.7「侧滑详情当前**不由列表触发**」，所以这一处不能用侧滑；审计是"读一份记录"（§5.3 → 弹窗）。
- **每条显示**（M17-02 的四项 + 定稿的字段）：**时间 · 工具 · 条目标题 · 结果**。
  - 工具名给中文（`create_item` → 新建条目），agent 侧的工具名放在 `ⓘ` 里。
  - 条目标题取不到（条目已删 / 不在范围）时显示「已不存在的条目」——**不给链接也不给 id**（避免把内部 id 当成可操作的东西）。
  - **结果四态**（`ok` / `conflict` / `denied` / `error`）用 `Pill`：成功=中性、冲突=警告色、被拒=危险色、错误=危险色。**`denied`（被拒）值得特别显眼**——它正是"agent 越权尝试"的证据。
- **只记写类工具**（M17-02 / 设计 §七），所以这个列表**天然是稀疏的**；只读调用不在其中。空态要写明这一点。
- **保留 90 天**，超过就查不到了。这条放 `ⓘ`（说明性文字，不平铺）。

## 六、空状态与状态边界（§6.1 全集）

| 状态 | 呈现 | 口径 |
|---|---|---|
| 列表加载中 | `hint-line`「正在读取…」 | 禁止静默等待 |
| **一个令牌都没有** | `EmptyState`（`Controls.tsx` 已有） | **为什么空 + 下一步做什么**（§5.4-3）：「还没有令牌。创建一枚，把它和下面的地址一起交给 Cursor、Claude Code 等工具，它们就能读写你的内容。」+ 一个「创建令牌」按钮（**空态里可以再给一个主操作**——它此刻就是这一屏唯一的推进动作） |
| 有令牌但某一枚审计为空 | 弹窗内 `EmptyState` | 「这枚令牌还没有执行过写操作。读操作（搜索、读内容）不记在这里。」 |
| 读失败 | 就地 `role="alert"` 的 `hint-line` | **不弹窗**（§6.1：错误就地提示）。**且不写空态**——读不出来时"还没有令牌"是假的（与附件管理页同一处理） |
| 达 20 上限 | 主操作置灰 + 旁注平铺原因 | §6.1 |
| 「指定文件夹」但一个没勾 | 提交时**就地**校验「至少选一个文件夹」；**不禁用提交按钮**（禁用要解释，就地报错更省事） | |
| 范围里只有加密空间可选 | 加密空间**不列进**文件夹复选列表（服务端也会拒）——不给一个必然失败的选项 | |
| 撤销中 / 创建中 | 按钮 `disabled` + 现有 `busy` 口径 | |

## 九、三个待拍板点

| # | 问题 | 我的建议 | 理由 |
|---|---|---|---|
| 1 | **审计**放行内展开（同 `MySharesPage` 的"改密码"）还是独立弹窗？ | **弹窗** | 90 天的记录可能几十上百条，内嵌展开会让每一行高度暴涨、列表参差；弹窗一次只展示一份 |
| 2 | **撤销**用行内二次确认（同 `MySharesPage`）还是 `ConfirmDialog`？ | **行内二次确认 + 后果平铺** | 与同族页面一致；行内确认时上下文就在眼前，不用在弹窗里重新描述是哪一枚令牌 |
| 3 | **文件夹范围**选"指定文件夹"后，列**所有**文件夹（顶层+子层）还是只列顶层、勾选自动含子？ | **只列顶层，勾选即含子** | 服务端的两层展开就是"选中的 + 其直接子"；列出子层会让用户以为要分别勾，且勾错会出现"勾了父又取消子"的矛盾状态。顶层带计数（如「工作（3）」）就够认 |

## 十、不做

- 令牌**编辑**（改权限 / 改范围 / 改期）：定稿只要求"随时撤销"。改权限等于让**已经发出去的凭据**权限变大，撤销重建更清楚。**后置**。
- 令牌用量趋势图、调用次数统计：定稿没有。
- 服务端设置 MCP 地址 / 路径：地址就是 `origin + /mcp`，没有可配项。
- 移动端布局：§2.4 未定稿，本屏按桌面稿实现，但**不得留下仅桌面成立的写法**（弹性布局、可点元素留触屏命中区、`viewport` 允许缩放）。
