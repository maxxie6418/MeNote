## 七、怎么用这份清单

- 每条回一个词即可：**做** / **不做** / **以后做**（例如"1-1 做、1-4 以后做、2-1 不做、4-1 以后做"）；
- 标"建议做"的多为**小改动且观感明显**（时间轴两列与节点、`more` 字形、空状态图标块、分组圆点）；
- 标"**需你定**"的多为**会改变屏形态**的（笔记行横竖、待办行/卡、首页重做、那年今日），
  改完用户的肌肉记忆会变，所以我不擅自动。

## 八、【v1.1 更正】"✅ 已完成"的项其实没生效 + 补登记 6 项漏掉的差异

**起因**：用户 2026-09-27 问"待办不是有原型页吗，为什么线上版本不一致"。

**查清的根因**：§一 / §二 里标"✅ 已完成"的那些项（1-1、1-2、1-3、2-1、2-2、2-3、2-5），
取值都写在 `apps/web/src/app/theme/app.css` 的**中段**「原型对齐块」里，而 M2 时代的同名旧块
（`.memopanel*` / `.timeline*` / `.memo` / `.taskpanel*` / `.kanban*` / `.taskcard*`）在**文件后段**——
CSS 同特异性下**后出现者胜**，于是旧值赢，**这批"完成"在界面上从未生效**（追溯 `5611710` 提交时的文件，
对齐块在 L1179、旧块在 L2678，落地即被压住）。全文件共 **15 个属性**被压回旧值（待办 9 + memo 6）。

`apps/web/test/css-cascade.test.ts`（断言此类覆盖为 0，含自证）。逐条细节见 `CHANGELOG.md` v0.5.1 条目。

> **教训（写给后来的自己）**："把覆盖追加在文件里"这种对齐方式，前提是"后面没有同名旧规则"。
> 这个前提一旦不成立，**改动会静默失效且没有任何机制报错**（用例查 DOM 与类名，都不看谁赢）。

## 十、【v1.3】用户上线后的反馈：三条「取值与结构之外」的硬伤（v0.5.4 修复）

用户部署后反馈"**memo 与原型页差异较大，待办稍微接近，但两个模式的界面显示都异常**"。
按同一套量法（真实 Chrome + 与本原型页同口径的几何量法）查出三条本文前九节**从未登记**的问题——
它们不是"取值不同"，而是**规则压根没生效或压根没写**：

| # | 屏 | 症状（实测） | 根因 | 修法 |
|---|---|---|---|---|
| 10-1 | Memo | 单行 Memo 卡片 **275px** 高（原型 97px）；正文块被 740px 上限 + `margin:0 auto` 挤在卡片中间（左右各 106px 空白） | `MemoItem` 的 `.memo__body` 带着 `markdown-body`，而 `MarkdownPreview` **自己又渲染一层** `.markdown-body`，而该类的阅读区样式（`max-width:740px; margin:0 auto; padding:var(--sp-5) var(--sp-6) 80px`）**叠了两层** | `.markdown-body` 收敛为**纯排版类**；阅读区宽度与内边距收进 `.docpane__body .markdown-body`；`MemoItem` 去掉重复类名 |
| 10-2 | Memo | 节点与圆点**悬空**（`.tl::before` 计算值 `content: none`）；时间轴铺满 1096px | **主干线从未实现**（原型 `.tl::before` 一直没搬过来）；`--cap:740px` 也没落地 | 补 `.timeline::before`（1px `var(--line)` @ `left:104px`）与 `.timeline{max-width:740px;margin:0 auto}` |
| 10-3 | 待办 | 「视图切换 + 添加待办」停在页头**中间**（`.tkhead__main` 604px / 页头 1146px）；看板模式**没有收窄**（滚动容器 1146px、看板 1106px，原型 917 / 877） | `.tkhead` 被写成 `display:flex`（原型只有 `position:relative`），子项被压成内容宽；看板那条只写了 `width:80%`，**缺 `flex:none`**，在 `flex:1` 子项上宽度声明不生效（原型那一行正是 `flex:none;width:80%;margin:0 auto`） | `.tkhead` 去掉 `display:flex`；`.taskpanel--board .taskpanel__body` 补 `flex:none`（连原有的 width/margin 一起） |

> 与"**写了但被 flex 吃掉**"。后者尤其隐蔽——CSS 里肉眼看着完全正确的 `width:80%`，
> 在 `flex:1` 的子项上**永远不生效**，而且没有任何机制会报错。**量几何**（而不是读样式表）
> 是唯一能发现它的手段；这三条都是靠量出来的数字才对上号的。
