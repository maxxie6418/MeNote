## 七、怎么用这份清单

- 每条回一个词即可：**做** / **不做** / **以后做**（例如"1-1 做、1-4 以后做、2-1 不做、4-1 以后做"）；
- 标"建议做"的多为**小改动且观感明显**（时间轴两列与节点、`more` 字形、空状态图标块、分组圆点）；
- 标"**需你定**"的多为**会改变屏形态**的（笔记行横竖、待办行/卡、首页重做、那年今日），
  改完用户的肌肉记忆会变，所以我不擅自动。

## 八、【v1.1 更正】"✅ 已完成"的项其实没生效 + 补登记 6 项漏掉的差异

**起因**：用户 2026-09-27 问"待办不是有原型页吗，为什么线上版本不一致"。

**查清的根因**：§一 / §二 里标"✅ 已完成"的那些项（1-1、1-2、1-3、2-1、2-2、2-3、2-5），
取值都写在 `apps/web/src/app/theme/app.css` 的**中段**「原型对齐块」里，而 M2 时代的同名旧块
（`.memopanel*` / `.timeline*` / `.memo` / `.taskpanel*` / `.kanban*` / `.taskcard*`）在**文件后段**——
CSS 同特异性下**后出现者胜**，于是旧值赢，**这批"完成"在界面上从未生效**（追溯 `5611710` 提交时的文件，
对齐块在 L1179、旧块在 L2678，落地即被压住）。全文件共 **15 个属性**被压回旧值（待办 9 + memo 6）。

**已于 v0.5.1 修复**：旧块里被取代的声明一律删掉、只有旧块提供的属性并入对齐块、并新增守卫
`apps/web/test/css-cascade.test.ts`（断言此类覆盖为 0，含自证）。逐条细节见 `CHANGELOG.md` v0.5.1 条目。

> **教训（写给后来的自己）**："把覆盖追加在文件里"这种对齐方式，前提是"后面没有同名旧规则"。
> 这个前提一旦不成立，**改动会静默失效且没有任何机制报错**（用例查 DOM 与类名，都不看谁赢）。
> 同类事故此前已发生过一次（v0.4.46 修 `.home-nav__title`），当时只就地改了那一条，没做全局排查。
