## 一、适用范围（先划边界，这条最容易搞混）

本稿只管**两个入口**：

| 入口 | 位置 | 打开什么 |
|---|---|---|
| 「添加 Memo」 | **Memo 页页头右侧** | 本窗口，`kind = "memo"` |
| 「添加待办」 | **待办页页头右侧** | 本窗口，`kind = "task"` |

**不在范围内**：

- ❌ **功能栏的快速录入框**（`Composer`）。它是另一套录入面，2026-10-01 刚把它压回两行，**本轮一个字不动**。
- ❌ 笔记。新建笔记仍走功能栏「新建笔记」/ 录入框「笔记」档，**不进本窗口**。
- ❌ `Ctrl/Cmd + N`。它打开的是**本窗口**、默认落在 Memo 档（沿用 `DESIGN.md` §6.3 已定口径，不改）。

> 历史上 `docs/modules/Menote-添加内容窗口-设计-v1.md` 曾把本窗口与功能栏录入框混称为「录入面」，
> 导致 2026-10-01 的一轮改动差点改错地方。本稿起，**两者在文档里必须分开称呼**：
> 「**添加内容窗口**」＝本稿对象；「**功能栏录入框**」＝`Composer`。

## 二、两个入口怎么弹（已接线，本轮不改）

两处入口**已经在弹同一个窗口**，不存在「待办要另做一个」这回事：

```
Memo 页头「添加 Memo」 ─┐
                       ├─→ addEntry.open(kind)  ← useAddEntrySlot（同一个 hook）
待办页头「添加待办」 ──┘        ↓
                    AddEntryDialog（同一个组件，kind 两值）
```

- `apps/web/src/app/App.tsx`：Memo `onAdd={() => addEntry.open("memo")}`、待办 `onAdd={() => addEntry.open("task")}`
- `apps/web/src/app/AddEntrySlot.tsx`：`useAddEntrySlot(onPublishMemo, onPublishTask)` 持有开关状态与 JSX
- 空状态出口同样指到 `open(kind)`：Memo 时间轴「添加 Memo」、待办列表「添加待办」

**类型由所在页面决定**（D1）。窗口内**不放** Memo/待办 切换控件——你在哪个页面点的添加，类型就已经定了，
再摆一个切换等于让用户改自己刚做过的选择。副作用：`Modal` 公共组件**不需要**加头部插槽。

## 四、属性区：三行、按需出现

### 4.1 分组

属性区按「**这条是什么 → 什么时候 → 归到哪**」分三组，每组一行：

| 行 | 组 | 控件 | 出现条件 |
|---|---|---|---|
| 1 | 这条是什么 | 记录日期 · 清单标记 | 仅 `kind = memo` |
| 2 | 什么时候 | 截止 · 优先级 | `kind = task` 常驻；`kind = memo` **确认为清单后**出现 |
| 3 | 归到哪 | 标签入口 · 标签 | 两档都出现 |

行尾（清单项计数 `N 项` + 一个 ⓘ `InfoHint`）挂在**最后一行**，不固定在行 1。

### 4.2 这推翻了 `DESIGN.md` §2.2 的一条已定结构尺寸

原 §2.2：「添加内容窗口字段行高 = **固定 26px、不换行**，越界横向滚动，不允许撑高」。
本轮改为：**属性区每行 `min-height: 26px`、允许换行、空组不渲染**。

- **为什么原规则要求占位**：本质是怕「**发布**」时高度变。发布不改任何内容，所以高度稳定；
  唯一的高度变化是用户主动点「设为清单？」展开行 2——那是有意展开，不是抖动。
- **空组不占位的收益**：待办档不会出现一条什么都没写的行（旧规则下 Memo 档那条 26px 空行就是这个毛病）。
- **回写要求**：见 §六。

### 4.3 控件形态（全部落在 `DESIGN.md` 已有家族内，不新增控件形态）

| 控件 | 形态 | 出处 |
|---|---|---|
| 记录日期 | `sw` 胶囊：日历图标 + 「今天」/ `10-01`，内套铺满但透明的原生 `<input type="date">` | §5.3 窗口字段行用 `sw`；不用 `display:none`（不可聚焦，与 §2.2「不得塌陷」同一口径） |
| 清单标记 | `sw` 胶囊，三态：占位「清单」（不可点）/ 「设为清单？」（amber，可点）/ 「✓ 已设为清单」（primary） | 同上 |
| 截止 | 原生 `type="date"`，带可见「截止」文字（沿用现状） | — |
| 优先级 | 盒式分段控件（高 / 中 / 低） | §5.3 互斥档位 |
| 标签入口 | `sw` 胶囊「+ 标签 · N」，点开**锚在旁边的短菜单** | §5.3 短菜单走菜单浮层，不是弹窗；方向按 §6.4-1「空间不足向上翻」 |

## 五、可配置属性：数据层允许什么

分界线是**「新建时能不能写」**——只有 `patch_meta` 支持、`ItemWriteMeta` 里没有的字段，本轮不做。

| 属性 | 结论 | 依据 |
|---|---|---|
| **标签 `tags`** | **做** | `ItemWriteMeta.tags: string[]` 新建即可写；`patch_meta` 也支持 |
| **截止 `task_due` / 优先级 `task_priority`** | **做**，清单 Memo 也给 | 两者都在 `ItemWriteMeta`；`publishMemo` 已透传 |
| **记录日期 `memo_at`** | **做**（仅 Memo 档） | `ItemWriteMeta.memo_at` 可写；现状被 `publishMemo` 写死 `now` |
| 状态 `task_status` | 不做 | 新建默认「待办」；待办视图本来就能拖 / 点改 |
| 置顶 `pinned` / 收藏 `starred` | 不做 | **只在 `ItemMetaPatch` 里**，`ItemWriteMeta` 没有——要在新建时设得扩协议，收益配不上 |
| 单篇加密 `enc_self` / 进加密空间 `in_enc_space` | 不做 | 服务端在 `ItemMetaPatchSchema` 里明确**拒绝给 Memo 做单篇加密**；`in_enc_space` 必须与 `folder_id` 同次补丁给且锁着时不可用；设计文档 §8.7 已定「输入框没有加密开关」 |
| 所属文件夹 `folder_id` | **本轮不做** | 技术上完全支持，但 Memo / 待办都是全局视图、诉求不强；文件夹树选择器是重控件，460→520px 也仍显挤；真要归档，建完再拖更顺手 |

### 5.1 三条实现要点

1. **清单 Memo 必须能设截止与优先级**。清单 Memo 就是 `is_task = 1`，而待办视图取的正是 `is_task === 1`
   （`features/tasks/model.ts`）——所以在 Memo 页点完「设为清单？」的下一秒，这条已经躺在待办视图里了。
   现状里字段行只剩一个 chip，**没有任何地方能设截止和优先级**，用户只能发出去再去待办视图改一次。
   根因：`publishMemo` 的 options **本来就收** `due` / `priority`，是 `AddEntryDialog` 只传了 `{ asTask }`，
   把它们丢在窗口里。**零协议成本**：字段、写入通道、md front matter 全都现成。
2. **记录日期按设置时区换算，保留当前时分秒**。`memo_at` 是毫秒时间戳，而时间轴分天走的是
   `groupMemosByDay(..., timeZone)`（默认 `Asia/Shanghai`，**不是本机时区**）。
   朴素写法「把 `2026-10-01` 转成当天 00:00」有两个问题：跨时区可能落到相邻一天；一堆补记条目全显示 `00:00`。
   正确做法：**只改年月日、保留当前时分秒，按设置时区构造**——补记的 Memo 在那组里排在最新位置、显示的时间也正常。
   实现上在 `features/memos/model.ts` 加一个「日期键 + 时分秒 → 时间戳」的纯函数（`dayKeyInZone` 的逆运算），
   那个文件本来就是纯函数带单测的 style，放得下。
3. **标签与正文 `#` 合并去重**。窗口点选的标签与正文派生的标签**合并去重**后一起写进 `tags`；
   正文来的显示 `--purple`、点选的显示主色，来源一眼可分。**标签写元数据，不写进正文。**

## 七、复用盘点（用户 2026-10-01 要求「尽量复用」）

### 7.1 真正共用的（实施时一份都不许抄第二遍）

| 层 | 共用物 |
|---|---|
| 装配 | `useAddEntrySlot` —— 开关状态 + JSX 一份，两个入口都指到它 |
| 窗口 | `AddEntryDialog` 一个组件、`kind` 两值 |
| 判定 | `TASK_ITEM_PATTERN`（`- [ ]`）、`TASK_PRIORITIES` / `TASK_PRIORITY_LABELS`（`@menote/mdcore`）、`deriveTags`、`deriveTaskFields` |
| 写入 | `publishMemo` 一条路径（`onPublishTask` 就是它的 `{ asTask: true, ...options }` 包装） |
| UI | `Modal` / `Button` / `Chip` / `SegmentedControl` / `InfoHint` |
| 时区 | `dayKeyInZone` + 新增的反向换算，同文件、同单测 style |

### 7.2 `ModeExtras` 是名存实亡的「复用」——本轮收掉

`ModeExtras` 挂在 `Composer.tsx`，注释写着「导出给 `AddEntryDialog` 复用，两个录入面同一份实现」。
**实际上它已经只有一个调用方**：功能栏录入框 2026-10-01 把属性行删掉后，`Composer.tsx` 的 JSX 里
只剩 `QuickComposer` + `composer__modes`，**根本没有渲染它**。全仓仅 `AddEntryDialog.tsx` 一处 import。

**为什么不该继续硬复用**：

1. 参数是 `mode: ComposerMode` 的三分支 if/else，其中 **note 档分支对窗口毫无意义**（笔记不进本窗口）；
2. 死守单行 26px，而本轮已定三行；
3. 要加记录日期与标签，都塞不进去。

**做法**：收成**窗口自己的** `AddEntryFields`（放 `fnbar/` 下、只服务窗口），
把 `Composer.tsx` 里那几处只为它存在的导出与注释清掉；**真正的共享留在原处**
（`TASK_ITEM_PATTERN`、`ATTRIBUTE_FOCUS_SELECTOR` 仍在 `Composer.tsx` 导出）。
**零行为变化**，只是把一个「假装被复用」的组件搬回它唯一使用方旁边。

## 九、验收点

1. Memo 页 / 待办页点右上角「添加」→ 弹出**同一个**窗口，`kind` 随页面变；窗口内无类型切换控件。
2. 窗口宽 520px；输入区 112px；`Ctrl+Enter` 发布、`Esc` 关闭、点遮罩关闭。
3. Memo 档行 1 出现「记录日期 + 清单标记」；**未**写 `- [ ]` 时清单 chip 不可点；
   写出 `- [ ]` 后变可点的「设为清单？」，**点一下**才变「已设为清单」，**不自动勾**。
4. 确认为清单后行 2 出现截止 + 优先级；发布后该条**同时**出现在 Memo 时间轴与待办视图，且截止/优先级已落库。
5. 记录日期留空 = 今天，`memo_at` 与现状**完全一致**；改日期后按**设置时区**落库，且时分秒保留当前值。
6. 标签可点选 / 新建，与正文 `#` 派生的合并去重后写进 `tags`；正文里**不出现**标签文本。
7. 空组不占位：待办档不出现「这条是什么」行；Memo 档未确认清单时不出现「什么时候」行。
8. 空内容时「发布」禁用，**原因在输入区下方可见**（不只在 `title` 里）。
9. 发布后：关窗 + toast + 条目立刻出现在当前列表。
10. **功能栏录入框行为与尺寸一字不变**（回归：`layout-invariants` 与 `fnbar` 用例必须仍全绿）。
11. `pnpm lint` / `pnpm typecheck` / `pnpm test` 全绿。
