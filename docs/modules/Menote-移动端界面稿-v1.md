## 〇、先读这一节：本稿是「初版方案」

**本稿不是定型结论。** 它记录的是「用户从三套候选里挑了一套」这个中间状态，作用是让下一次评审有具体对象，而不是让实现开工。

因此：

1. **不要据此写界面代码。** `DESIGN.md` §2.4 目前写的是「窄屏 / 移动端布局【后续定】」，禁止项 #16 明确禁止在定型前自行发明移动端布局——本稿是「定型这件事」的过程产物，不是定型本身。
2. **不要据此改 `DESIGN.md`。** 改 `DESIGN.md`（改、删、覆盖都算）与改 `wiki/` 一样，必须先得到用户明确同意（见 `AGENTS.md`「先确认再动」）。定型后同步 `DESIGN.md` 是**另一件事**，需要单独确认。
3. **§九的待确认项没清空之前，本稿保持「草案」。** 其中第 1 条（三段还是四段）与第 5 条（页签与输入行的上下顺序）会影响骨架，属于阻塞项。
4. 本稿的数值是**界面稿实测值**，不是 `DESIGN.md` 的【已定】值。凡与 §2.2 结构尺寸表重合的（顶栏 54px）沿用既有令牌；新增的（输入行 44px / 展开 33%）**尚未进入任何定稿**，定型时要走「改仓库不变量 → 重跑回归脚本 → 回写本文」的流程。

## 一、这一版的范围

**做什么**：移动端（窄屏）主界面的一套纵向骨架 + 三个档位的内容组织 + 快捷录入的常态与展开两态。

**不做什么**（本稿有意的边界）：

- 不动桌面骨架。顶栏 + 左功能栏 + 右主操作区（`DESIGN.md` §2.1）在宽屏照旧，本稿只描述窄屏怎么折。
- 不新增颜色、字号、圆角、间距。全部取自 `DESIGN.md` §3.3 / §4.3 的既有令牌。
- 不改任何功能规则（哪些视图、哪些字段、排序与筛选口径），那些归 `wiki/` 与 `docs/modules/` 的专项稿。
- 不定义登录页、设置页、搜索页、加密空间在移动端的形态 —— 它们各自另起一份，本稿只保证骨架给它们留了位置。

## 二、骨架与尺寸

### 2.1 骨架

```
┌───────────────────────────────┐
│ ① 顶栏            站名 · 头像 │  54px
├───────────────────────────────┤
│ ② 三档页签  首页 · 笔记 · Memo│  44px（下划线）
├───────────────────────────────┤
│ ③ 快捷输入行 / 输入面板        │  44px / 33%
├───────────────────────────────┤
│                               │
│ ④ 内容区（随档位变化）         │  剩余全部
│   首页 / 笔记 / Memo           │  唯一滚动容器
│                               │
└───────────────────────────────┘
```

自上而下的顺序就是**导航优先于录入**：先确认「我在哪一档」，再决定「我要记什么」。

### 2.2 尺寸表（界面稿实测，**未定稿**）

| 区域 / 元素 | 值 | 来源 |
|---|---|---|
| 顶栏高 | 54px | 沿用 `--topbar-h`（`DESIGN.md` §2.2【已定】） |
| 三档页签高 | 44px | 触屏命中区底线（§2.4-3），**新增** |
| 快捷输入行（常态） | 44px | **新增** |
| 快捷输入面板（展开） | 屏高 **33%** | 用户描述「占屏幕大概三分之一」；360×740 框下实测 240px |
| 内容区 | 剩余全部 | **新增** |
| 手机框基准 | 360 × 740 | 界面稿取 iPhone 级别窄屏；不是规范值 |
| 内边距 | `--sp-3` / `--sp-4` / `--sp-6` | 走 §4.3 刻度，无新数值 |
| 卡片圆角 | `--radius-lg` 14px；列表行 `--radius` 10px | §3.3 |
| 字号 | `--fs-title` / `--fs-body-lg` / `--fs-body` / `--fs-small` / `--fs-micro` | §3.3，无新字号 |

**宽度**：本稿所有块都是流式（`flex` + 百分比 + `min()`），**不出现「固定宽 + 绝对定位」**（§2.4-1 / 禁止项 #17）。手机框本身用 `width:min(360px,100%)`，窄于 360px 的机型不溢出。

**安全区**：贴底元素需要 `env(safe-area-inset-bottom)`。本稿的输入行不贴底，但要为将来「输入面板贴键盘」的变体留出这条要求。

## 三、逐块说明

### 3.1 ① 顶栏（54px）

| 项 | 内容 |
|---|---|
| 现有块 | **站名（品牌）+ 头像**，两块 |
| 主操作 | 无（头像是入口，不是推进动作） |
| 待确认 | 桌面顶栏是 **6 块且顺序不可变**（`DESIGN.md` §2.5-1，有脚本断言）。窄屏塞 6 块不现实，本稿**只落了两块**，并在界面稿里用虚框标出「同步胶囊」的候选位置。移动端顶栏保留几块 = §九 第 2 条，未定 |
| 明确不做 | 不在顶栏放搜索框（窄屏无空间；搜索入口另议，见 §九 第 6 条） |

### 3.2 ② 三档页签（44px）

| 项 | 内容 |
|---|---|
| 造型 | **下划线页签**（无框、无底、选中项带 2px 主色下划线） |
| 依据 | `DESIGN.md` §5.3：顶部**同级导航**（首页 / Memo / 待办）用下划线页签，**不用**盒式分段控件；§2.5-4 要求它与紧邻的录入模式切换必须能一眼分开 |
| 三档 | 首页 · 笔记 · Memo（**待办的去向未定**，见 §九 第 1 条） |
| 状态 | 选中项用 `--primary-ink` 文字色 + 主色下划线；未选中为 `--text-2`。不以悬停表达选中（§2.4-2） |
| 无障碍 | `role="tablist"` + 每项 `role="tab"` + `aria-selected`；键盘可达且焦点可见（§6.2） |

### 3.3 ③ 快捷输入区（常态 44px / 展开 33%）

**两态**：

| 态 | 高 | 内容 |
|---|---|---|
| 常态 | 44px | 一行占位文案「随手记点什么…」，整行可点 |
| 展开 | 33%（240px） | ① 录入模式（笔记 / Memo / 待办，**盒式分段控件**）② 输入区（最小 40px，弹性）③ 模式附加项（**固定 26px、不换行**，越界横向滚动）④ 发布按钮 |

**沿用桌面录入框的既有约束**（`DESIGN.md` §2.5-2、§2.2）：

- 附加项容器**固定高度 26px 且不换行**，不得用 `display:none` 让容器塌陷；
- 切换录入模式**只换内容不换高度**；
- 追加项胶囊用 `sw`（可切换），与只展示的 `chip` 不合并（§5.3）；
- 发布是本区域**唯一**的实心主色按钮（§5.1）。

**展开是「就地撑开」，不是浮层**：不设遮罩，内容被下推。这样它与「菜单 / 弹窗」在语义上分得开（§5.3）。

### 3.4 ④ 内容区（剩余全部）

| 项 | 内容 |
|---|---|
| 滚动 | 本屏**唯一**的滚动容器（§2.7 / §2.4-4）。`body` 不滚动，页签与输入区不滚动 |
| 宽度 | 流式占满，受 §2.3 的宽度上限约束（首页卡片组 920px、Memo 时间轴 740px）——窄屏下都不触发 |
| 主操作 | **无**。本屏的主操作是输入区的「发布」，不在内容区 |
| 切入 | 点条目按各自视图的既有规则处理（笔记在右列直接打开的规则在窄屏变成整屏切换，细则另议） |

## 四、三个档位的内容

| 档位 | 内容 | 空状态 |
|---|---|---|
| **首页** | 最近编辑 + 收藏，两组卡片；每组一个「全部」入口 | 两组都空时给「还没有内容 → 去写第一条」，不给两段灰字 |
| **笔记** | 笔记本树：两层（根 / 子文件夹）+ 条目叶子；节点带计数与「待上传」标记；组头带「＋ 新建文件夹」 | 「还没有笔记」+ 出口（新建笔记 / 新建文件夹） |
| **Memo** | 按天分组的时间轴（天边界按设置时区）；条目带时间、标签、清单图标、置顶标记 | 「还没有 Memo」+ 出口（把焦点送回输入区） |

**口径约束**（不论布局怎么定都成立）：

- 笔记视图**不列 Memo**（Q8）；
- Memo **不提供收藏**（Q8）；
- 空状态必须写清「为什么空 + 下一步做什么」（§5.4-3）；
- 界面辅助文案默认不写，说明性文字收进 `InfoHint`；但**警告、破坏性后果、错误校验、实时计数必须保持可见**（§5.4-1/2）。

## 五、交互规则

| # | 规则 | 依据 |
|---|---|---|
| 1 | 点页签切档位：内容换、输入面板**自动收起**（回常态 44px） | 用户描述「按完之后上面的快捷输入窗口会向上缩回」 |
| 2 | 点输入行展开；再点（或发布、或按 `Esc`）收起 | §6.4-5 的 `Esc` 统一退出手势 |
| 3 | **页签的位置不随输入区变化而移动** —— 这是选定方案与 A 方案的关键差别（A 里输入区在页签之上，一收一放页签会上下跳） | 本稿的设计取舍，见 §八 |
| 4 | 展开/收起时长 **200ms**，只表达空间关系，不做弹跳 | §6.8 |
| 5 | 可点元素命中区 ≥44×44px（视觉尺寸不变，用内边距补足） | §2.4-3 |
| 6 | 不以悬停作为唯一入口；状态用选中类表达 | §2.4-2 |
| 7 | 所有可点元素键盘可达、`focus-visible` 可见、图标按钮带 `aria-label`；可点 `div` 改 `button` | §6.2 |
| 8 | `viewport` 允许缩放，**禁止** `user-scalable=no` / `maximum-scale=1` | §2.4-3 / 禁止项 #17 |
| 9 | 尊重 `prefers-reduced-motion`：开启减弱动效时取消位移与缩放 | §6.2-6 |

**展开态的键盘问题（必须在定型前看）**：键盘弹起约 280px 时，顶栏 54 + 页签 44 + 输入面板 240 = 342px，内容区只剩约 **118px**。打字时不需要看内容，所以可以接受；但**模式附加项（截止 / 优先级）必须挤进这 240px 内**，不能靠滚动去找。界面稿的「关键态」里有这一帧。

## 八、备选方案与取舍

三套候选都在 `docs/scratch/Menote-移动端界面三方案-2026-09-26.html` 里（可交互）。

| | 结构 | 优点 | 代价 |
|---|---|---|---|
| A · 输入优先 | 顶栏 → 输入区（展开 33%）→ 页签 → 内容 | 与桌面功能栏「新建 → 录入框 → 导航区」自上而下**骨架同构**，改动最小 | 常态占掉 33% 屏；输入区一收一放，**页签位置会跳** |
| B · 内容优先 | 顶栏 → 页签 → 内容吃满 → 底部常驻输入条 | 内容首屏最大；输入面板贴键盘，不占常态空间 | 输入入口离开顶部，与桌面骨架对应关系最弱 |
| **C · 折中（选定）** | 顶栏 → **页签** → 顶部常驻输入行（44px）→ 内容 | 保留「输入框在顶部、随时能记」；常态只占 44px；**页签位置固定**；展开是就地撑开、不需要遮罩 | 比 A 多一次「点开」；展开时内容被推出屏外 |

**选 C 的理由**：既保住用户最初「输入框在顶部、随手能记」的意图，又不让录入入口常态吃掉 1/3 屏幕；同时把页签提到输入区之上，消掉了 A 里「切档时页签上下跳」这个手感问题。

**C 相对用户最初描述的一处顺序调整（重要）**：用户最初描述是「输入框在上、三档切换在下」。C 把**页签提到了输入行之上**。理由是导航优先级高于录入（先确认在哪一档，再决定记什么），且这样页签不动。用户已选定 C，但这条调整建议在定型时再确认一次（列入 §九 第 5 条）。

| 7 | **桌面 §2.5-2 的「录入框 136px + 导航 y=252」不变量在窄屏的等价值** | 回归脚本（不阻塞） | 需要一条窄屏不变量（如「页签 y 坐标不随输入区状态变化」），由第 5 条定完后一起写 |

## 十、定型后可用于验收的检查点

以下检查点**现在不作为验收依据**（本稿未定稿），列出来是为了让定型时一次对齐：

1. 顶部四块的顺序与高度：顶栏 54 → 页签 44 → 输入行 44 → 内容区剩余。
2. 输入面板展开 = 屏高 33%；页签的 y 坐标在收起 / 展开两态下**完全一致**。
3. 三档切换后输入面板回到常态 44px。
4. 可点元素命中区 ≥44×44px；`viewport` 允许缩放。
5. 无横向滚动；`body` 不滚动；内容区是唯一滚动容器。
6. 三档内容与各自空状态都有出口。
7. 浅色 / 深色两套主题下文字对比度均 ≥ WCAG AA；橙色文字走 `--primary-ink`。
8. 界面实现处不出现裸色值 / 裸字号 / 越界间距（由既有守卫拦截）。
9. 键盘弹起时模式附加项（截止 / 优先级）仍在输入面板内可见、可点。
