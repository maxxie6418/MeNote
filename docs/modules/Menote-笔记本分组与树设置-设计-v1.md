## 一、现状与事实（先说清，免得重复劳动）

- **左侧功能栏的笔记本树是存在的**：`features/notes/ui/FolderTree.tsx`（两层、折叠三角、引导线、计数、更多菜单；2026-09-27 加的折叠与引导线）。它只有**建过文件夹**才有节点，空账号下 `roots = []`，**既没有空态也没有明显入口**——这是"看不到文件树"最可能的直接原因。
- **中间列在「全部笔记」下是扁平的**：`filterByView` 对 `{kind:"notebook", folderId:null}` 返回全部条目，`NoteList` 直接铺开，没有分组、没有文件夹。
- 原型：功能栏是**文件夹树（只有文件夹、两层）**（`prototype/menote-prototype.html:850-890`），中间列是"选中那个文件夹的条目"扁平列表 + 头部显示文件夹名（`notes-tables.html:631-644`）。**原型没有"文件夹+文件"混合树**——所以本设计不照搬 Obsidian，按用户选的 B 做。

## 二、中间列按文件夹分组（方案 B）

### 2.1 什么时候分组

| 视图 | 行为 |
|---|---|
| `{kind:"notebook", folderId:null}`（全部笔记） | **按文件夹分组**：先「未分类」（`folder_id === null` 的条目），再每个第 1 层文件夹一组（组内先自己的条目、再各子夹的二级分组）。空分组不渲染 |
| `{kind:"notebook", folderId:"f1"}`（选中某个笔记本） | 保持"只显示它直接包含的条目"（**不**递归到子夹），但把它的**子夹**作为二级分组头列出来（可点进子夹） |
| 最近编辑 / 收藏 / 标签 / 搜索结果 | **不分组**，保持现有扁平列表（这四个视图没有"笔记本"上下文） |

分组只在 `notebook` 视图出现，避免"最近编辑也按文件夹切碎"这种反直觉。

### 2.2 结构与样式

```
.listpane__scroll
 ├─ .notelist__group             ← 分组头（文件夹图标 + 名字 + 「N 条」+ 折叠三角）
 │   └─ .notelist__rows          ← 组内条目（沿用现有 NoteRow，不加新行样式）
 └─ .notelist__group.is-sub      ← 二级（子夹）分组，缩进一档
```

- 分组头复用 **已有的** `.tasklist__gl` 那一族"灰色组名 + 计数微标"语言（`features/tasks` 的取值），保持全站一套行语言；**不新增视觉语言**（`DESIGN.md`）。
- 组头**可折叠**（点击折叠这一组，状态只在本组件内，与 `FolderTree` 的折叠同一套做法）；折叠状态**不进设置**（纯展示）。
- 计数 = 组内条目数（子夹分组只算自己的直接条目，与卡片计数口径一致）；**实时计数必须可见**（禁止项 #8）。
- 组内条目继续用 `NoteRow`（**行的 `memo` 化不能被破坏**：分组后仍是"只重渲染变化的行"——框用 `useMemo` 分组结果，行 props 保持原始值/稳定引用）。

### 2.3 与既有约束的接缝

- **两层限制**：分组只到第 2 层（`MAX_FOLDER_DEPTH`），第 2 层不再有子分组；
- **隐私门禁**：分组前先过 `filterByView` 的门禁（`canShowInList`），锁定时空间内条目不出现，分组也自然为空；
- **排序**：组内沿用现有"最近编辑倒序"；**组间顺序**照 `FolderTree`（根在前、同级按名称 `localeCompare`），「未分类」固定第一组；
- **性能**：分组是纯函数 `groupNotesByFolder(items, folders)`（新纯函数 + 单测），2000 篇下仍是一次 O(n) 分组。

## 三、树里是否显示条目（设置项）

用户口径：「是否要在文件树里显示文件，可以做成设置里可配置项」。

- **契约**：`UserSettings.notebook = { show_items?: boolean }`（optional + 默认值，与 `task_view` / `memo_view` 同一做法；旧客户端不传不 422）。
- **默认值待你拍板**（我的建议：**`true`（显示）**——你反馈的正是"看不到文件"，默认能看到更符合预期；但原型形态是只显示文件夹，所以也可默认 `false`）。
- **行为**：`true` → 树里每个文件夹下缩进列出**它直接包含的条目**（笔记 / 表格，用 `NoteRow` 的图标语言：`note` / `table`；只显示类型图标 + 标题，不带摘要与时间，避免树被撑胖），点条目**直接打开**（与列表点击同一动作）；
  `false` → 只显示文件夹（贴原型）。
- **上限与性能**：每个文件夹最多列出 **50 条**，超出给一行「还有 N 条…」→ 点击把中间列切到该文件夹（避免 2000 篇时树把 DOM 撑爆）。条目来自已经在内存里的 `allItems`（按 `folder_id` 建索引，一次 O(n)）。
- **设置入口**：加在设置页「通用」的界面偏好里（与主题、待办筛选条形态同一张卡）——**设置页正在重构**（见 `docs/modules/` 的设置页稿），所以这一行**跟着设置页重构那一批一起落**；契约与树的行为本轮先按上面定稿。
