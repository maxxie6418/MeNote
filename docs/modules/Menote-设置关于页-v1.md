## 一、范围

- 设置里新增一个分类 **关于**（需求 §7.5 的 10 个分类之外的**第 11 个**，排在导航最后）。
- 页内**只有两项**：**版本号**、**项目 GitHub 地址**。用户明确"其他的暂时不用写"——不放许可协议、更新日志、致谢、检查更新、作者信息。
- 账户快捷菜单（点头像弹出）的**账户头**显示版本号。

## 二、设置 › 关于

结构沿用既有设置壳（`.setcard` / `.setrow`），无新增控件、无新增视觉语言：

| 行 | `setrow__name` | `setrow__desc` | 右侧 |
|---|---|---|---|
| 1 | 版本 | 当前部署的版本号 | `v0.3.2`（纯文字） |
| 2 | 项目地址 | 源码仓库（GitHub） | 链接 `https://github.com/maxxie6418/MeNote`，`.link` 样式，`target="_blank"` + `rel="noreferrer noopener"` |

- 页头由设置壳统一渲染：「关于 · 版本号与项目地址 · 共 N 个分类」（N 由实现按可见分类算：owner 7、成员 6）。
- **空状态**：不需要（页面恒有内容）。
- **主操作**：没有——这是纯信息页；唯一可点的元素是仓库链接。
- 文案守则：不出现"检查更新""最新版本"之类尚未实现的暗示。

## 三、账户快捷菜单

- **位置**：账户头（`.acct`）内，用户名、`{owner|成员} · 本地实例` 之下的**第三行**。
- **样式**：复用 `.acct__sub`（`--fs-micro` + `--muted`），**不新增 CSS**。
- **文案**：`MeNote v0.3.2`。
- **行为**：不占菜单项位、不参与「快捷菜单」配置清单（`quick_menu`）、不可键盘聚焦、不可点。
- **取舍**：更标准的放法是菜单底部加一个 footer 槽；`DropdownMenu` 目前没有该槽，加槽属**公共组件改动**，本屏先用账户头第三行。等出现第二个需要 footer 的地方（例如回收站/备份的状态行）再一起加，避免为单个用途扩公共接口。

## 四、版本号从哪来（只有一处来源）

- 唯一来源 = **根 `package.json` 的 `version`**（AGENTS「版本号规范」）。
- **构建期注入**：`apps/web/vite.config.ts` 与 `apps/web/vitest.config.ts` 各自 `define.__APP_VERSION__`，值来自 `import rootPackage from "../../package.json" with { type: "json" }`（带 import attributes，规避 Vite 将来切 native config loader 的告警）。**前端不复制版本号**。
- 新增 `apps/web/src/app/about.ts`：导出 `APP_VERSION`（未注入时退化为 `dev`，**不编造版本号**）与 `PROJECT_REPO_URL`，供「关于」页与账户菜单共用。
- **实测**：`pnpm build` 产物 `apps/web/dist/client/assets/index-*.js` 内含版本串与仓库地址；首屏 135.5 KB（上限 200 KB）。
- 测试：`vitest.config.ts` 同样注入，所以「关于」页的版本断言读的是真实版本号（不写死字符串）。
