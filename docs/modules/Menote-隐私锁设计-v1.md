## 一、术语与前提

### 1.1 术语

| 术语 | 含义 | **不是什么** |
|---|---|---|
| 加密空间 | `folders` 表中 `is_enc_space = 1` 的内置行：每账户一条、depth = 0、不可删除、不能建第二个【定稿 M08-07】 | 不是密码学加密。名字里的"加密"只是文案，它与单篇加密不属同一类机制【已定·用户确认】 |
| 隐私范围（scope） | 隐私锁**一次解锁**所覆盖的内容集合：默认含加密空间，可配置含 Memo 及其衍生的待办，预留后续扩展位 | 不是"另一个容器"，它是一份**类别清单**，决定门禁覆盖谁 |
| 隐私锁 | **范围门禁** ＋ **备份出站加密**，两者共用同一把隐私密码 | 不加密存储中的内容（见 P1） |
| 单篇加密 | `items.enc_self = 1` 条目的**独立门禁**，逐篇解密 | 不属于隐私范围；不受隐私锁解锁影响【已定·用户确认】 |
| 隐私内容 | 加密空间内条目（`in_enc_space = 1`）＋ 在范围内的 Memo 与待办 ＋ 单篇加密条目（`enc_self = 1`） | — |
| 范围解锁 | 输入隐私密码后，范围内全部内容对界面可见 | 不解开任何单篇加密条目 |
| 逐篇解密 | 对单篇加密条目单独输入隐私密码，**仅该篇**在本次会话内可读 | 不是"解开隐私锁顺带解开" |
| 会话态 | 只存在于浏览器内存、**不落库、不同步**的门禁状态：隐私锁解锁态、单篇已解密集合、档位计时器 | 不是一条数据，换设备/换标签页重来 |

### 1.2 三条前提

**P1 内容明文存储【已定·用户确认 2026-09-26】**：D1 与本机 IndexedDB 中，正文、标题、文件夹名、附件**都是明文**；隐私只是 `items.enc_self` / `items.in_enc_space` / `folders.is_enc_space` / `folders.in_enc_space` 这几个元数据标记。因此锁定只影响**前端渲染与检索可见性**，不影响存储，也不产生任何加解密动作。

**P2 隐私密码只有两个用途**【定稿 M08-09 技术说明】：① 前端门禁校验（本地 verifier）；② 备份出站加密（内容密钥 K）。服务端**不参与**密码校验。

**P3 保护边界如实告知**【定稿 M08-01】：启用时与确认框里都必须写清边界——不防已登录账号、不防服务端与本机缓存/日志、不防对备份文件的离线爆破。已接受的元数据泄露：条目数量、大小、时间、置顶与收藏、附件数、层级（定稿 v7.4 §6.5）。

### 1.3 保护边界（实现与文案共用同一口径）

| 能防 | 不能防 |
|---|---|
| 身边的人偷看屏幕：锁定时范围内内容整体占位或从列表消失，搜索、Memo、待办、筛选结果一并处理 | 知道你**登录密码**的人（登录后可直接调接口拿明文） |
| 第三方备份里直接翻到私密内容：隐私条目出站前强制加密 | 服务器管理员、拿到 D1/R2 备份的人 |
| 误分享、误让 AI 读到：MCP 与分享对隐私内容一律不可见（见第五章） | 本机浏览器缓存被翻（IndexedDB 里是明文） |
| 爆破者的时间成本：PBKDF2-SHA-256 600k（KDF 与参数见待写的第三～四章） | 专业者绕过备份文件的密码 |

## 二、三种机制对照

### 2.1 对照表

| | 机制一：隐私锁（范围门禁） | 机制二：单篇加密（独立门禁） | 机制三：MCP 可见性（独立配置） |
|---|---|---|---|
| 保护对象 | 隐私范围（加密空间 + 可配置的 Memo/待办 + 扩展位） | 单篇笔记/表格（`enc_self = 1`），留在原位、标题明文 | 不是锁：各内容类别对 MCP 的可读性 |
| 入口 | 顶栏胶囊、解锁框、点范围内的内容 | 编辑器「更多」菜单、条目上的锁标识 | 设置 › MCP 的令牌配置 |
| 解锁方式 | 一次输隐私密码 → 范围内**全部**可见 | **逐篇**输隐私密码，每篇状态独立【已定·用户确认】 | 不涉及解锁；由令牌配置决定 |
| 时效 | 三档：本次会话（多标签共享，全部标签关闭即锁）/ N 分钟无操作（默认 5）/ 当前设备长期（手动锁）【已定·用户确认】 | **本次浏览器会话**；可手动锁上（本篇 / 全部单篇）【已定·用户确认】 | 与隐私锁状态**无关**，不随范围设置变化 |
| 与对方的关系 | — | **不受隐私锁解锁影响**；隐私锁全开时它照样锁着 | 与隐私范围**解耦**：Memo 在范围内也不等于 AI 不能读（反之亦然） |
| 锁定/未解密时表现 | 空间不可展开、范围内容占位或消失、不进搜索 | 明文标题 + 锁标识，正文不渲染、不进搜索 | — |
| 计数 | 加密空间节点与文件夹树**照常显示条目数**【已定·用户确认】 | 计入容器计数 | **不计入**：MCP 侧的条目数与空间节点都不含隐私内容（见 5.3） |
| 备份出站 | 范围内内容强制加密 | 同样强制加密 | — |

### 2.2 三条不变式

1. **三者互不替代**：解锁隐私锁 ≠ 解开单篇；把 Memo 加入范围 ≠ 禁止 AI 读 Memo；任何一种都不能推出另一种。
2. **可以叠加**：空间内条目若同时带 `enc_self = 1`，则先进隐私锁（可见其位置与标题）、再进单篇门（才能读正文）。
3. **只有两个维度会改动"谁能看见什么"**：界面门禁（范围 × 隐私锁状态）与 MCP 令牌配置。两张矩阵**互不联动**（见 5.3）。

## 三、隐私范围与配置

### 3.1 成员与默认值

| 成员 | 默认 | 可否配置 | 判定来源 |
|---|---|---|---|
| 加密空间（含其内部文件夹与条目） | **在范围内** | 不可移出——它是范围的本体【本文决定】 | `folders.is_enc_space = 1` / `items.in_enc_space = 1` |
| Memo | **在范围内** | 可开可关 | 账户级设置项 `privacy.scope.memo` |
| 由 Memo 衍生的待办（清单视图 / 看板） | 跟随 Memo 开关 | 同 Memo，**一个开关管两者**【本文决定】 | 同上 |
| 后续内容类型 | 不在范围内 | 逐个加入 | 扩展位（见 3.4） |

> Memo 默认在范围内，与既有定稿 M08-16 的"Memo 浏览需要隐私密码（默认开）"一致；该设置项在 M3 里改为范围配置的一部分，文案与落点见待写的第七章。

### 3.2 范围变化的语义

- 加入范围 / 移出范围**都是元数据操作**，不涉及任何加解密，锁定态下同样可执行。
- **移出范围立即恢复普通可见**：Memo 移出后锁定时照常显示；空间内的条目不能单独移出范围（它们由空间归属决定，移出＝移出空间，那是另一条规则 M08-10）。
- 范围变化**不影响**已存在的单篇加密标记——那是机制二，有自己的开关。
- 范围变化不产生版本、不进回收站、对 MCP 可见性**无影响**。

### 3.3 配置项与落点

| 配置项 | 落点 | 值 |
|---|---|---|
| 范围成员 | `user_settings` 的 `privacy.scope` | `memo: boolean`（space 恒真，不落库或恒为 true） |
| 默认档位 | 同上 | `tier: 'session' \| 'minutes' \| 'device'` |
| N 分钟时长 | 同上 | 1 / 5 / 15 / 30 / 60，默认 5 |
| 解锁时可搜索加密内容 | 同上 | `unlockSearch: boolean`（作用范围见 5.1） |

设置随 `user_settings` 整份同步（M2 已有通道，不参与游标）；`privacy.scope` 写成"内容类别 → 布尔"的映射，**新增类别只加一项，不改门禁判定签名**（签名见待写的第三章）。

### 3.4 后续扩展位的约束

新内容类别加入范围时必须满足两条：① 它是**可枚举的内容类别**（不是单条数据）；② 它的"锁定表现"能在界面上明确表达（占位、隐藏或收起三选一）。不满足就不进范围——否则门禁会出现"半遮半掩"的状态。

## 四、锁定与解锁：状态、时效、触发

### 4.1 状态集合

| 机制 | 状态 | 说明 |
|---|---|---|
| 隐私锁 | 未启用 / 已锁定 / 已解锁 | 未启用时不存在单篇加密（前置：已启用【本文决定】） |
| 单篇加密（逐篇） | 未加密 / 已加密·未解密 / 已加密·已解密（本次会话） | 与隐私锁状态**正交**：解锁隐私锁不解开它，锁定隐私锁也不清它的已解密集合 |

### 4.2 三档时效【已定·用户确认 2026-09-26】

| 档位 | 覆盖 | 重锁触发 |
|---|---|---|
| 本次会话 | 隐私范围全部 | 所有 Menote 标签页关闭（多标签共享同一解锁态） |
| N 分钟 | 隐私范围全部 | 无操作 N 分钟后（N 默认 5） |
| 当前设备长期 | 隐私范围全部 | 手动"锁定此设备"（选择时须勾选风险确认） |

**已作废**：原"仅本次查看"档（本会话内只放当前一篇/一个空间）与"标签页隐藏即锁"——两者在 2026-09-26 的修订中先后被合并/取消【已定·用户确认】。定稿 M08-04 的四档表与 M08-05（Q14）随之改写，见附录 B。

### 4.3 触发清单

**解锁**：点顶栏胶囊 / 打开范围内的内容 / 在 Memo 或待办视图点"解锁" / 打开单篇加密条目（进的是**单篇**解锁框）。

**锁定**：
- 顶栏胶囊「立即锁定」——默认**锁全部**：清隐私范围解锁态 ＋ 清单篇已解密集合【本文决定；理由：点"立即锁定"的心理预期是"立刻都别看了"】；
- 档位到期（N 分钟无操作 / 最后一个标签页关闭）；
- 「锁定此设备」（设备长期档）；
- 登出（沿用认证设计：登出即锁定）。

### 4.4 锁定时做与不做

**做**：
1. 未保存的改动按**普通保存流程**先入库（不涉及加解密）；
2. 加密空间收起、范围内内容切占位或从列表移除；
3. 搜索与筛选结果中的隐私内容、Memo 立即消失；
4. 状态标识切到锁定态；剩余 30 秒时胶囊闪烁一次并提示（文案见待写的第九章）。

**不做**：
1. 不做任何加解密、不重写内容、不产生版本；
2. **不清本地缓存**（明文仍在 IndexedDB，符合 P1/P3，文案不得暗示"数据已保护"）；
3. 不改动数据的 `rev` / `sync_seq`（锁定是纯前端状态）。

### 4.5 单篇的逐篇解密

- **逐篇**：每篇独立状态，互不联动【已定·用户确认】。解开 A 篇不会让 B 篇可读。
- **时效**：本次浏览器会话；关闭标签页自然失效。
- **多标签共享**：会话内在同源标签页之间共享【本文决定，与隐私锁会话档一致】，走现有 `BroadcastChannel` 通道，不落库、不同步。
- **手动锁上**：编辑器/锁标识上的「锁上此篇」；顶栏「立即锁定」的"锁全部"；另有"锁上全部单篇"入口。
- **密码**：复用同一把隐私密码；"逐篇"指**门禁状态独立**，不是每篇一个密码【本文决定】。若将来要"不启用隐私锁也能单篇加密"，需要独立口令与 per-item verifier，属另一套设计。
- **不改数据**：解密只是门禁状态，正文、标题、附件都不重写。

### 4.6 离线

- 解锁与锁定**可离线**：verifier 有本地缓存时校验全在浏览器完成【定稿 M08-03】。
- 启用 / 修改 / 重置 / 关闭隐私锁**需联网**（要写服务端）。
- 本地 verifier 缓存是否随登出清除，取决于 Q22（登出是否清除本机缓存）——**Q22 未决，M3 开工前必须定**【待确认】。

### 4.7 计数口径【已定·用户确认 2026-09-26】

| 计数种类 | 举例 | 锁定时的口径 |
|---|---|---|
| **容器计数** | 加密空间节点、文件夹树、首页统计 | **始终计入**隐私内容，不因锁定改变（推翻定稿 M08-07 与 §9.2 的"不显示条目数"） |
| **筛选结果计数** | 标签视图、搜索结果条数 | 与列表同源，锁定时**不含**隐私内容【本文决定】——否则会出现"数字 12、列表 0 条" |
| **MCP 计数** | `list_folders` 返回的条目数 | **不含**隐私内容，且空间节点不出现在 MCP 的文件夹树中（见 5.3） |

锁定时空间**仍不可展开**：只显示数量，看不到标题与正文。

## 五、可见性矩阵（两张，互不联动）

### 5.1 界面可见性（隐私锁状态 × 内容类别）

| 内容 | 隐私锁已锁定 | 隐私锁已解锁 |
|---|---|---|
| 加密空间节点 | 显示，**含条目数**，不可展开 | 可展开、可浏览（两层文件夹 + 列表/正文双栏） |
| 空间内条目 | 不出现在任何列表、搜索与筛选结果中（仅计入容器计数） | 仅在加密空间内可见；**不进**最近编辑 / 收藏 / 标签，不进标签统计 |
| Memo 与待办（在范围内） | 两个视图整体占位；不进搜索 | 正常显示；可搜【定稿 M09-02】 |
| Memo（不在范围内） | 正常显示 | 正常显示 |
| 单篇加密条目 · 已加密未解密 | 明文标题 + 锁标识，正文不渲染，不进搜索 | **同左**（不受隐私锁解锁影响） |
| 单篇加密条目 · 已解密（本次会话） | 正文可读、可编辑；可搜（受"解锁时可搜索"开关约束） | 同左 |
| 普通内容 | 正常显示、可搜 | 正常显示、可搜 |
| 快速录入框 | 可正常写 Memo（写入永远免密）【定稿】 | 可正常写 |

补充口径【本文决定】：
1. "解锁时可搜索加密内容"这一个开关**统一作用**于空间内条目与已解密的单篇条目；关掉时两者都不进搜索结果。
2. 单篇条目的可搜**不再额外要求隐私锁处于解锁态**——它已逐篇解密即可（与机制二的独立语义一致）。

### 5.2 MCP 可见性（令牌配置 × 内容类别）

| 内容 | 对 MCP |
|---|---|
| 加密空间节点与空间内条目 | **一律不可见**（与其计数；永不可见，与令牌配置、隐私锁状态都无关）【定稿 M17-03 / §6.13】 |
| 单篇加密条目 | **一律不可见**【同上】 |
| Memo | 令牌勾选"包含 Memo"时可见；与隐私范围、隐私锁状态**都无关**【定稿 M17-01/03】；默认不勾选＝不可见 |
| 令牌范围外的文件夹 | 不可见【定稿】 |
| 回收站中的条目 | 不可见（定稿里标【补全】，本文沿用） |

### 5.3 不变式（实现与测试必须守住）

- **I1**：MCP 可见集合 ＝ 令牌范围 ∩ 非隐私内容 ∩（Memo 需勾选"包含 Memo"）∩ 非回收站，且**与隐私锁是否解锁无关**。
- **I2**：界面矩阵与 MCP 矩阵**不联动**：改范围配置不动令牌，改令牌不动范围。
- **I3**：隐私内容对 MCP 永久不可见是**硬约束**——服务端所有面向 MCP 与兜底搜索的查询必须带 `enc_self = 0 AND in_enc_space = 0`，该判定**集中一处**，并有集成测试覆盖（现有两处重复实现见待写的第三章）。
- **I4**：MCP 返回的条目数不含隐私内容；空间节点不出现在 MCP 的文件夹树里。

## 六、与相邻功能的边界

| 相邻功能 | 边界 |
|---|---|
| 搜索（M09） | 本地索引与查询层同源过滤；服务端兜底搜索用同一份判定；详见 5.1 与 I3 |
| 附件与版本（M4） | 跟随所属条目的门禁：隐私条目的附件明文存储、锁定时占位【定稿 M10-02】；加密文章的版本需该篇已解密才能查看/对比 |
| 分享（M5） | 隐私内容不可分享；条目被加上隐私标记时已有的分享**自动撤销**（分享不自动恢复） |
| 导出与备份（M5） | 隐私内容出站**强制加密**；手动导出默认加密，"解密导出"需先范围解锁或该篇已解密 |
| 同步（M13） | 隐私只是元数据标记，**不引入新的同步实体**；会话态（解锁态、已解密集合、计时器）**不同步**——换设备要重新解锁 |
| 登出（M01） | 清会话态并锁定；是否清本地 verifier 缓存见 4.6（Q22 未决） |
| MCP（M6/M17） | 见第五章；令牌配置界面在 设置 › MCP，**不在隐私锁设置页**【已定·用户确认】 |
