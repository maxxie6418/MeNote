## 一、先说清两件事

### 1.1 M5 已经交付了什么、没交付什么

| 部分 | M5 状态 | 本轮要不要做 |
|---|---|---|
| **格式契约**（`packages/shared/src/backup.ts`：`BACKUP_FORMAT` / 路径函数 / manifest schema / `COMPLETE` 提交标记 / `normalizeSnapshotPath` 路径安全） | ✅ 已在 | **复用，一行不改**（拍板点 ④「与 M5 zip 内层同构」就落在这里） |
| **信封**（`packCryptoBlob` / `unpackCryptoBlob` / `derivedKeyInput`） | ✅ 已在 `@menote/shared/src/crypto.ts` | **复用** |
| **浏览器侧导出 / 导入 / 恢复**（`features/backup/{export,import,restore}.ts` + 设置 › 备份页） | ✅ 已在 | **复用**，本轮只在那一页**加**「外部备份目标」卡片 |
| **服务端快照物化**（D1 → R2 `snap/{uid}/`） | ❌ **没有**——M4 只在 Cron 里留了「③ 快照队列【接口位】」 | **要做** |
| **外部目标管理与推送**（WebDAV / S3 适配器、差异计算、续推状态机） | ❌ 没有 | **要做** |
| `export_queue` 表 | ❌ **表都没建**（`export_queue` 只在《数据模型与迁移设计》§3.4 的表清单里，M4 建的是别的六张） | **要做** |

**所以这不是"给已有的东西加个开关"**——服务端那一半整块都要写。但**格式与信封都是现成的**，不另立一套。

### 1.2 一处范围收窄（「立即备份」：**由「不做」改判为「做最小版」**）

设计 §四 的 API 里有 `POST /api/backup/targets/:id/run`「**立即备份**：浏览器循环调用，每次一批，返回进度与剩余量（架构 §12.4 定稿）」。

**初稿（本计划 v1）写的是「本轮先不做它」**。**批 4 落地时改判为「做最小版」**（v0.7.5），依据是：批 3 把状态机做完之后，「推一次」就是**一行调用**——它复用同一个 `pushOneRound`，不另写任何逻辑。真正贵的是**浏览器循环调用 + 进度条 + 中断续传**那一整套界面，那部分**仍未做**（见 §六 批 4 与 §七）。

现状一句话：**一轮就是一批**（架构 §14.3 的硬限额），想全量推完就多点几次或等 Cron。

**配套的缺口**：隐私条目从服务端快照恢复时，正文是**信封形态**，客户端「先解开信封再存」那一步**尚未实现**（`jobs/snapshot.ts` 文件头第 4 条）。**补上之前不能直接把服务端快照当普通 zip 导入。**

### 3.1 批 1 落地时的订正与发现

**① 步 1.5 的「范围校验」前提是错的。** 写计划时照着 MCP 的 `folder_scope` 想到了范围校验，但**备份目标根本没有文件夹范围**——设计 §三 的目标记录里没有这个字段，备份永远是整实例一份（这与「M5 导出」的口径一致：导出也不选文件夹）。**照计划实现会写出一段校验一个不存在的字段的代码。** 目标记录里唯一的"范围"是 `user_id`，跨租户隔离由它保证（用例已覆盖）。**不是设计变了，是计划抄错了模型。**

**② 抓到并修掉一个真 bug：WebDAV Basic 认证遇非 Latin1 口令必崩。** 原实现用 `btoa(\`${username}:${secret}\`)`——口令含中文时 `btoa` 直接抛 `InvalidCharacterError`。**更要命的是它抛在"创建适配器"那一步**，在路由的 `try/catch` 之外，于是本该是 401 的失败变成了 500/503。已改为**每次请求现算 + 先 UTF-8 编码再 base64**（`TextEncoder` → `Uint8Array` → 二进制串 → `btoa`）。**这类"在错误边界之外抛"的错误最坏**：它把一个明确的凭据问题伪装成服务端故障。

**③ 一处跨 feature 的复用抽取。** `formatRelative`（"3 小时前"）原住在 `features/mcp/model.ts`，备份卡片也要用。**从 backup 去 import mcp 是反向依赖**——两条业务线互不认识，一条删了另一条就断。已提升为 `app/format.ts`，两边各自 import，**输出口径一个字没改**，MCP 的既有断言未动。

**④ `kind` 的 CHECK 与枚举都只放 `webdav` / `s3`，不放 `git`。** 放进去等于对外宣告"支持 Git 备份"，而 Git 的 tree/commit 编排本轮明确不做。**枚举里出现一个不实现的选项，比不写更糟。**

**批 2 验收点**（`a379230`）

- [x] 物化一轮后 R2 里出现 `snapshot/manifest.json` + `COMPLETE` + 至少一篇笔记 —— **用 `verifySnapshot` 整包校验通过**（M5 已在用的那个函数；半截包当完整包是最糟的失败方式）
- [x] **普通条目出站是明文、隐私条目是密文**（**两条都断言**。只断言"有加密"的话，一个把所有条目都加密的实现也能过；只断言"没加密"的话，隐私条目明文出站也能过）
- [x] **信封能独立解回原文**（**不信实现**：自己去 `/api/crypto/reset` 拿 K 独立解一遍，拿回原文才算数）

**批 2 计划自身写错的地方（两条）**

① **步 2.1 的「生成 `snapshot/` 树」不能是全量。** Cron 一天 96 轮，全量重写一个 500 条目的库是**每天 4.8 万次 R2 写**，且 99% 的轮次什么也没变。**改成增量**：游标记在**迁移 `0008` 新建的 `user_snapshot_state`**（没往 M1–M3 的定稿表上加列）。**不是"照设计实现"，是"照设计的量级重新算一遍"**——这与批 1 那次"外部子请求 50"是同一类订正。

② **步 2.2「Memo 月份文件」没有做**。设计 §二 提到它，但**客户端随写入提交的那个月份键服务端拿不到**（Memo 的月份是客户端派生后写进 `memo_at` 的，服务端只有那个时间戳）。**如实登记为未做**，不做一个"用服务端时间戳近似月份"的版本——那会让备份里的 Memo 归属与本机不一致，而这类偏差很难被发现。

- [x] 启用一个目标后，Cron 几轮内把文件推到远端
- [x] **一轮的外部 PUT ≤ 40**（用例数 `fetch` 次数）

**批 3 计划自身写错的地方（三条）**

③ **「适配器」这一项其实在批 1 就写好了**（步 1.7）。批 3 实际只做差异计算与状态机——本计划初稿把适配器列在批 3 是重复计工。

④ **差异计算只有"新增 / 变更"两组，没有"删除"组。** **删除不可能从快照算出来**：条目永久删除后快照里不会有任何痕迹说它曾经存在过。**唯一的信息源是永久删除那一刻**——`services/trash-purge.ts` 的第 9 步先查真实存在的 id、算出 `del:` 前缀的包内路径、写进 `export_queue`。**这带来一处对既有文件的侵入**（永久删除多一条语句，9 → 10，`trash.test.ts` 那条 ≤45 的用例随之改数），已在 CHANGELOG 记明。

⑤ **`delete_policy='sync'` 的远端删除不需要"备份已推过"这个判断。** 初稿想的是"只在推过的文件上删"，实际**直接删 `del:` 队列里记着的路径**即可：那些路径之所以在队列里，正是因为本机已经没有它了。**多一个"是否推过"的判断只会引入"忘了判断就删错"的新风险。**

- [x] 「推一次」的结果**平铺在那一行上**，且**三种含义分开说**：没推成（原因平铺）/ 没东西可推（**不是失败**）/ 推了一批还有剩（**一轮一批的硬限额下这是常态，不是出错**）

- [x] 三条边界：正常返回 / **别人的目标 id → 404 且与「不存在」的响应逐字相同** / **没会话 → 401 且一个外部请求都不发**

## 七、本轮不做

| 不做 | 理由 |
|---|---|
| **Git 目标** | 拍板点 ① 首期 WebDAV + S3（Git 的 tree/commit 编排最重、价值面窄）。`kind` 的枚举与 CHECK 里**也不放 `git`**——放进去等于宣告已支持而实际没有 |
| **「立即备份」的进度条 / 中断续传界面** | 见 §1.2：改判为做最小版（`推一次`），**浏览器循环那一整套界面仍未做** |
| **隐私条目从服务端快照恢复时"先解开信封"** | 配套缺口，同上。**补上之前不能把服务端快照当普通 zip 导入** |
| **Memo 月份文件** | 见批 2 订正 ②：客户端派生月份键服务端拿不到，不做一个"用时间戳近似"的版本 |
| **附件字节进快照树** | 同一桶内按内容哈希已有，再存一份是存储翻倍、收益为零；由推送侧按需直拷（manifest 的 `attachments` 是空数组——**不声称自己没有的东西**） |
| **M16-04 恢复** | 走 M5 已交付的 zip 导入，本设计不含 |
| **定时目标的用量曲线** | 定稿没有 |
| **移动端** | 用户 2026-10-03 排除 |
