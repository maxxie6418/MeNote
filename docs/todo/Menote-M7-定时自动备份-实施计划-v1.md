## 一、先说清两件事

### 1.1 M5 已经交付了什么、没交付什么

| 部分 | M5 状态 | 本轮要不要做 |
|---|---|---|
| **格式契约**（`packages/shared/src/backup.ts`：`BACKUP_FORMAT` / 路径函数 / manifest schema / `COMPLETE` 提交标记 / `normalizeSnapshotPath` 路径安全） | ✅ 已在 | **复用，一行不改**（拍板点 ④「与 M5 zip 内层同构」就落在这里） |
| **信封**（`packCryptoBlob` / `unpackCryptoBlob` / `derivedKeyInput`） | ✅ 已在 `@menote/shared/src/crypto.ts` | **复用** |
| **浏览器侧导出 / 导入 / 恢复**（`features/backup/{export,import,restore}.ts` + 设置 › 备份页） | ✅ 已在 | **复用**，本轮只在那一页**加**「外部备份目标」卡片 |
| **服务端快照物化**（D1 → R2 `snap/{uid}/`） | ❌ **没有**——M4 只在 Cron 里留了「③ 快照队列【接口位】」 | **要做** |
| **外部目标管理与推送**（WebDAV / S3 适配器、差异计算、续推状态机） | ❌ 没有 | **要做** |
| `export_queue` 表 | ❌ **表都没建**（`export_queue` 只在《数据模型与迁移设计》§3.4 的表清单里，M4 建的是别的六张） | **要做** |

**所以这不是"给已有的东西加个开关"**——服务端那一半整块都要写。但**格式与信封都是现成的**，不另立一套。

### 1.2 一处范围收窄（**要用户点头**）

设计 §四 的 API 里有 `POST /api/backup/targets/:id/run`「**立即备份**：浏览器循环调用，每次一批，返回进度与剩余量（架构 §12.4 定稿）」。

**本轮先不做它**，理由：

- 它是**手动**触发（"立即备份"），而 M7 第 4 项的目标是"定时自动备份"（M16-01/02/03）；
- 它要浏览器循环调用 + 进度条 + 中断续传，是**一整套界面**，与自动备份的状态机同源但不同入口；
- 自动备份做完后，手动版只是"多一个入口"，届时加是薄的。

**若你希望这轮就一起做**，说一声——它会让本批多出设置页的一块界面与一段轮询逻辑。

**批 1 验收点**

- [ ] 能在设置里建一个 WebDAV 目标并测试连接
- [ ] **任何接口的响应里都搜不到凭据明文**（用例逐个响应断言）
- [ ] 别人的文件夹 id 填进范围 → 422；加密空间行 → 422
- [ ] 删目标**不动远端文件**（只清账本）
- [ ] `pnpm test` / `lint` / `typecheck` / `check:size` 全绿

## 四、批 2 拆步（快照物化 + 出站加密）

| 步 | 做什么 |
|---|---|
| 2.1 | `jobs/snapshot.ts`：从 D1 读该用户的条目 / 文件夹 / 设置 / 附件元数据，按 `packages/shared/src/backup.ts` 的路径函数生成 `snapshot/` 树，写 R2 `snap/{uid}/`，**最后写 `COMPLETE` 提交标记** |
| 2.2 | Memo 月份文件（该月全部 Memo 拼成一份），月份键用客户端随写入提交的值 |
| 2.3 | 出站加密：**隐私条目**（`enc_self=1` / `in_enc_space=1`）按 §7.3 信封加密，**普通条目明文**（M16-02 定稿） |
| 2.4 | 接线 Cron 的 ③ 槽（`services/jobs.ts` 现在的「快照队列【接口位】」） |

**批 2 验收点**

- [ ] Cron 跑一轮后 R2 里出现 `snapshot/manifest.json` + `COMPLETE` + 至少一篇笔记
- [ ] **普通条目出站是明文、隐私条目是密文**（用例两条都断言）
- [ ] 出站包**不含 `user_crypto` 任何字段**（设计 §五的安全底线）
- [ ] 同一轮跑两次幂等（游标 + 条件删，不重复写）

## 五、批 3 拆步（推送 + 接线）

| 步 | 做什么 |
|---|---|
| 3.1 | 差异计算：目标游标（`cursor_seq`）得出 **新增 / 变更 / 删除** 三组路径 |
| 3.2 | 推送状态机：**一轮一批、批内 ≤40 个外部 PUT**（架构 §14.3 的硬限额），推不完下一轮续推；`delete_policy='sync'` 才执行远端 DELETE，`append_only` 只记日志 |
| 3.3 | 调度档位（每天 / 每周）只决定"某天推不推"，**不决定一轮推多少** |
| 3.4 | 接线 Cron 的 ⑤ 槽；单轮加密配额 **2 MB**（2–4 ms 估计值的下界） |
| 3.5 | 凭据每轮从包裹里解开用完即弃，**不进日志、不进错误消息** |

**批 3 验收点**

- [ ] 启用一个目标后，Cron 几轮内把文件推到远端
- [ ] **一轮的外部 PUT ≤ 40**（用例数 `fetch` 次数）
- [ ] `append_only` 时**不执行远端 DELETE**
- [ ] 凭据不出现在任何日志 / 错误消息里
- [ ] 推到一半失败 → 下一轮从游标续推，不从头再来

## 六、批 4 拆步（运行态界面）

| 步 | 做什么 |
|---|---|
| 4.1 | 目标行显示**最近一次结果与时间**（`ok` / `partial` / `failed`） |
