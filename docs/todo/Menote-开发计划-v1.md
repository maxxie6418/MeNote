## 三、里程碑详细计划

### M0 骨架与部署链路（目标：今天搭好，明天能访问）

**包含功能点**：无业务功能点，纯工程底座（对应架构 §2.3）。

子计划：
1. 初始化 pnpm workspace：`apps/web`（Vite + React 19）、`apps/worker`（Hono + TS）、`packages/shared`；配置 TS 引用与 lint。
2. Worker 最小路由（`/api/health`）+ Static Assets 托管前端构建产物；`wrangler.jsonc` 配 D1 绑定（先建空库）。
3. 接通 GitHub → Workers Builds 自动部署（架构 §15.5）；建立 dev / production 两个环境。
4. CI（架构 §15.2）：lint + tsc + 首批测试；入口文件行数预算检查（§2.3.1）。
5. 写 wiki/guides/ 本地开发上手；README「怎么跑」更新。

**验收**：push 到 main 后自动部署；线上域名可打开页面并调通 `/api/health`；本地 `pnpm dev` 一键起前后端。
**前置文档**：无（本地开发 guide 是产出之一）。

### M1 核心闭环（目标：真实多端同步跑通）

**包含功能点**：M01 账户与认证（M01-01~05；M01-06 只留占位）、M04 笔记最小集（**M04-01 新建、M04-04 自动保存、M04-05 大小显示与上限**；M04-02 是加密入口，属 M3，v1.2 勘误）、M13 同步最小版（M13-01 离线优先最小、M13-02 同步时机与状态、M13-03 多标签页选主、M13-04 冲突副本最小版，架构 §6.1/§6.3）。另含 M18 的**最小设置入口**（M01-02/04/05 的唯一界面落点）。

子计划：
1. **专项设计先行**：《同步引擎设计》《数据模型与迁移设计》《认证与会话设计》三份均已产出（`docs/modules/`，评审中）；开工前完成评审。
2. **迁移机制**：按《数据模型与迁移设计》§4 落地运行时自愈迁移（`db/selfheal.ts` + `db/migrations/0001_init.ts`），**不把 `wrangler d1 migrations apply` 放进部署脚本**；首次部署零手工步骤。
3. D1 表结构第一批（8 张）：`app_meta` / `users` / `sessions` / `auth_throttle` / `user_settings` / `folders` / `items` / `item_bodies`（按新隐私模型建，不带密文列）；`tombstones` 与 `r2_gc_queue` 归 M4。
4. Worker：auth 路由与服务（prelogin / 登录 / 注册首位 owner / 登出 / me / 改密、会话中间件、CSRF）、`/api/admin/registration`（owner）、items/folders 路由、sync 最小版（拉元数据 / 取正文 / 新建 / 全文保存 / 元数据更新）。
5. 前端：Dexie schema（items/bodies/drafts/folders/outbox/syncState）+ outbox + 同步引擎最小版（退避、幂等、409 冲突副本、Web Locks 选主）；CodeMirror 6 编辑器接入（2s/30s 自动保存、256KB 放宽、硬上限拦截）；**界面骨架按 DESIGN.md 一次成型**（`AppShell` / `Topbar` 6 块 / `ListPane` / `DocPane`，M2 只填内容不重搭，避免"为单个功能另做页面骨架"）+ 登录/注册页 + 最小设置壳（左列 184px 分类导航 + 账户与安全 + 实例管理）。
6. 首次真实多端验证：两台设备（或浏览器+手机）注册登录互见。

**验收**：断网可继续编辑、联网自动补同步；两设备数据一致；刷新不丢数据；`pnpm lint/typecheck/test` 全绿；线上可登录取正文。
**前置**：三份专项设计稿评审通过；用户拍板项无。

### M2 组织与录入（目标：日常可用的记录工具）

**包含功能点**：M02 界面框架与导航（按原型定稿：顶栏 6 块、功能栏、录入框三行、双栏视图）、M03 笔记本与文件夹、M06 Memo、M07 清单/待办、M09 搜索、M18 设置（两栏分页框架 + 通用页）。

子计划：
1. 界面框架**在 M1 已成型骨架上填内容**（顶栏 6 块与左右两栏 M1 已搭；本步补功能栏四区、录入框三行、【实测】不变量 136px / y=252、双栏视图集合），对照 components.md 组件清单与 DESIGN.md。
2. 笔记本树 + 文件夹（≤2 层）+ 移动/重命名；`items` / `folders` 路由补全（trash/restore、`POST /api/batch`）。
3. Memo 时间轴/瀑布流 + 待办列表/看板（复用快速录入框切模式）。
4. 新建 `packages/mdcore`：front matter、标签与任务字段派生（前后端同一份实现）+ 搜索（`workers/search.worker.ts` 本地索引 + `Intl.Segmenter` 中文分词与 bigram 兜底）。
5. 设置补齐两栏分页：导航最终形态 10 个分类，但**只显示已实现的分类**（M2 落通用 / 账户与安全 / 编辑器 / 隐私锁占位 / 版本与回收站入口占位），并把 `user_settings` 纳入 sync 载荷。
6. **跨里程碑取舍（v1.2 明确）**：M06-02 的 Memo 图片（单条 ≤5 张、粘贴/拖入、缩略图）依赖 M4 的附件管线与 R2，**M2 不做图片上传**；M2 先保证"文字 Memo + 标签 + 清单字段"闭环，图片随 M4 补齐（届时刷新 M06-02 的验收走查）。若用户要求 M2 带图片，需同时把 R2 绑卡决策提前。

**验收**：按功能拆解 v2 各条验收口径走查；verify 原型脚本覆盖的交互路径在实现中均可走通；隐私门禁判定集中在一处（M3 才能只改一处翻转）。
**前置**：**DESIGN.md 视觉章（§3 配色/字族/字号刻度/圆角刻度/阴影）与 §4.3 间距刻度在本里程碑开工前定稿**（只换令牌层，不改结构）；R2 绑卡决策若要在 M2 覆盖 Memo 图片则需提前拍板。

### M3 隐私锁（目标：隐私模型完整落地）

**包含功能点**：M08-01~16（启用/解锁/锁定/档位、加密空间、单篇加密、移入移出、修改与重置隐私密码、相关设置）。

子计划：
1. crypto/ 前端模块：PBKDF2 门禁校验、会话锁定状态机（无密钥保管，架构 §7.1/§7.2）。
2. 门禁接入全局：导航占位、列表隔离（canShowIn）、Memo 门禁、编辑器锁标识与状态栏倒计时。
3. 加密空间视图 + 单篇加密开关 + 移入移出（普通元数据操作，锁定时可用）。
4. 备份导出加密的 crypto-format 包先行（纯函数，M5 消费）。

**验收**：功能拆解 §9.2 门禁矩阵逐格走查；锁定状态下所有入口行为符合矩阵。
**前置**：专项设计《隐私锁》完成；Q25 按推荐方案（允许）实现。

### M4 内容完整性（目标：个人笔记应用的完整形态）

**包含功能点**：M05 表格、M10 附件与图片、M11 版本历史、M12 回收站与永久删除。

子计划：
1. 表格：列结构定义/增删改（Q16 建议案）、单元格编辑、表格视图。
2. 附件管线：R2 绑定、上传/下载直传、缩略图（media worker）、GC job（此时需 R2，确认绑卡）。
3. 版本历史：快照生成（编辑时 + Cron）、历史浏览与回滚。
4. 回收站：软删 + 30 天后 Cron 永久删除（§12.3）+ 恢复。

**验收**：图片粘贴上传显示、版本回滚内容正确、回收站恢复原位/根目录规则正确。
**前置**：R2 绑卡决策（推荐接受）。

### M5 分享与备份（目标：数据可出可入、可分享）

**包含功能点**：M14 分享、M15 导出、M16 备份与恢复。

子计划：
1. 专项设计《分享》（含 origin 决策落地）与《备份与外部解密工具》。
2. 分享：创建/撤销 + share.html 查看器（笔记只读 / 表格只读+图册，Q18 建议案）。
3. 导出：单篇 Markdown / 全量 ZIP；备份：WebDAV/S3 适配器 + 出站加密信封（复用 crypto-format）+ Cron 备份状态机（§12.4）。
4. 恢复导入（Q20 建议案：只导入空账户）+ 外部解密工具验证。

**验收**：备份文件用外部独立工具能解开；恢复演练记录成文（wiki/guides/）。
**前置**：分享 origin 决策。

### M6 扩展与上线收尾（目标：正式可用）

**包含功能点**：M17 MCP、M19 数据与实例管理、M15/M16 收尾、PWA 完整离线（§3.6）。

子计划：
1. MCP：令牌管理、工具集（读/写/搜索）、限速中间件。
2. 数据管理/实例管理设置页；全量 ZIP 导出入口（Q21 建议案归位）。
3. Service Worker 缓存策略完整落地；性能预算实测（§14）校准。
4. 上线前检查：部署指南成文（wiki/guides/）、使用说明（面向家人）、Runbook 初版。

**验收**：全部功能点走查完毕；性能预算达标；使用说明可供非技术家人照做。
**前置**：无外部决策。

## 四、测试与验证策略（每阶段适用）

- **分层**（架构 §15.1）：packages/* 纯函数单测 → Worker services 集成测试（miniflare + 本地 D1）→ 前端关键路径测试 → 每里程碑真实部署冒烟。
- **同步正确性是 M1 起的最大风险**：outbox/冲突/墓碑的用例在专项设计中先行列出，实现一项测一项。
- **界面对照**：布局以原型为准、行为以功能拆解验收口径为准；每里程碑结束跑一遍对照清单。
- **每里程碑交付物**：可访问的线上环境 + CHANGELOG 记录 + 走查结果。
