## 一、起因与结论

用户反馈线上待办与原型不一致。查下来是**两层原因叠加**，性质完全不同：

1. **A 组（真 bug）**：v0.4.44–v0.4.50 那批「按原型对齐 memo 与待办」的取值**从未生效**——对齐块写在
   `apps/web/src/app/theme/app.css` 中段，M2 时代的同名旧块写在文件后段，CSS 同特异性下**后出现者胜**，
   旧值赢。**15 个属性**被压回旧值（待办 9 + memo 6），与原型不符的 14 处。
   → **v0.5.1 已修**，并新增守卫 `apps/web/test/css-cascade.test.ts`（断言此类覆盖为 0，含自证）。
2. **B 组（结构/交互没做）**：线框定稿里 2026-09-27 已定的几处待办结构调整**根本没实现**，
   而《原型还原差异清单》§二**一条都没登记**（它只列了 2-1…2-5），于是没进任何计划。
3. **另有一层部署事实**：用户线上仍是 v0.4.49 **之前**的构建（待办还是卡片式、没有复选框）。
   这条不解决，改什么都看不见。

## 四、待拍板的 3 个点（**这几条不确认不动**）

### 1. 页头的「说明 ⓘ」要不要新造 `InfoHint` 组件

`DESIGN.md` §5.4-1 要求"说明性文字一律收进 `InfoHint`（ⓘ + 悬停）"，原型页头也确实有那个 ⓘ。
但**全仓目前没有 `InfoHint` 组件**，既有写法是可见的 `hint-line`（`TableColumnManager` 的注释明确写了"照既有写法"）。
新造它等于**新增公共组件**（要同时改 `wiki/components.md` 与 `DESIGN.md` §5.5 的图标用法），按规矩得你点头。

**三选一**：①新造 `InfoHint`（并回写 wiki/components.md）；②这一处先不写 ⓘ（"待办是清单 Memo 派生的视图"这类口径依赖 `HintLine` 或干脆省）；③整屏不做说明位。

### 2. 详情浮层接到哪里

- 定稿（`prototype/menote-framework.html` 07）：待办**详情用滑出侧栏**，已被记入 `components.md` 的 `taskDetail`。
- `DESIGN.md` §6.7【已定】：侧滑详情**能力保留，但不由条目列表触发**；明确说"未来可接的是**表格图册的行详情与待办看板的卡片**"。
- `DESIGN.md` 禁止项 **#15**：禁止"把侧滑详情重新接回列表的条目点击"（理由是条目点击一律"在右列直接打开"，但**待办是单栏占满、没有右列**）。

→ **看板卡片接详情 = 已明确允许**；**清单行接不接**处在灰区（#15 的措辞针对"条目列表"，待办清单不是双栏的条目列表，但字面上会撞）。
**请定**：①只接看板卡片；②看板卡片 + 清单行都接（按原型，原型两处都点了）；③先不做详情（B-4 整条推迟）。

### 3. 筛选条两种形态要不要现在做

定稿说"两种都留，将来在设置里让用户自选"，也就是需要一个**用户设置项**（并落到同步/备份的公共契约里）。
这属于 `AGENTS.md`「先确认再动」清单里的"公共类型、公共配置"。

**三选一**：①只做基线（胶囊横排）+ 把悬浮形态的样式备好、设置项以后加；②连设置项一起做（要动
`packages/shared` 的设置契约 + 设置页 UI + 用例）；③完全按定稿的预览条那样先不做。

## 六、拍板结论与落地结果（v0.5.2）

**用户 2026-09-27 的选择**：①页头说明 ⓘ → **新造 `InfoHint` 公共组件**（并回写 `wiki/components.md`）；
②详情浮层 → **看板卡片与清单行都接**（并批准在 `DESIGN.md` §6.7 加一句界定）；
③筛选条两形态 → **连用户设置项一起做**。

六项全部落地：B-1（`InfoHint` + 页头收一条 + 「添加待办」接 `focusComposer("task")`）、
B-2（筛选条进 `.taskpanel__body`，与列表同上限居中、看板下不限宽并把滚动容器收到 80%）、
B-3（三组名 + 「隐藏已完成」开关 + 已完成分组收起，同一份状态；看板下收起状态筛选与开关）、
B-4（`features/tasks/ui/TaskDetail.tsx`：绝对定位盖在界面上、不铺遮罩、390/≤1080px 330、260ms、Esc 与 × 收起）、
B-5（分组头分隔线 `.tasklist__rule`）、B-6（契约 `task_view.filter_form` + 设置页一行单选组 + 两形态样式）。

**实现期另定下的 6 条口径**（都写进了代码注释或文档，这里汇总一笔）：

1. **详情面板不做跨 feature 的 `Drawer`**：`wiki/components.md` §八 的通用判定是"原型中被 3 处以上复用"，
   现在只有待办一个消费方，所以落在 `features/tasks/ui/`；预留的 `app/ui/Drawer.tsx` 仍留到表格图册
   行详情（M05-08）也接上时再抽。
2. **原型的「子清单」与「活动记录」两块不做**：我们的模型里没有对应数据（清单不是独立类型、
   是加在 Memo 上的标记；也没有逐条活动流），**不编数据**。详情＝标题 + 属性 + 描述（Memo 正文原文）+ 底部动作。
3. **底部不放「删除」**（原型有）：删除是破坏性操作（`DESIGN.md` §6.5 要二次确认），
   而详情是"临时查看属性"；主操作区已有删除入口。要加就单独立项（要连确认框一起做）。
4. **列表 / 筛选条的 920px 上限写成 `.taskpanel` 上的局部变量 `--task-cap`**，不升全局令牌
   ——`DESIGN.md` §2.3 的"内容宽度上限"表里没有待办这一屏（要不要补进那张表另说）。
5. **sprite 新增 `close` 字形**（原型 `#i-x`）：关闭按钮走图标而不是文本字符 `×`（§5.5-1）。
   名字 ↔ 字形的一一对应由既有守卫盯着。
6. **`App.tsx` 行数预算（500）**：`focusComposer` 改为可接一个档位（`focusComposer(mode?)`），
   首页快捷入口与待办「添加待办」各收成一行；备忘：这个文件只剩个位数余量，下次再加东西要拆。

**顺带修掉的既有隐患**：`apps/web/test/app-navigation.test.tsx` 的夹具此前把整份 `UserSettings`
形状抄了一遍（M3 加 `privacy`、M4 加 `version_trash`、这次加 `task_view` 都会报
`Cannot read properties of undefined`）——改成 `{ ...DEFAULT_USER_SETTINGS, … }`。

**部署那一层仍未解决**：用户线上是 v0.4.49 之前的构建（不是代码问题），要看效果必须先让
Workers Builds 重新构建或 `pnpm deploy`；本机 wrangler 未登录，无法代验。
