## 二、第 4 条的根因（值得记一笔）

`useNotesWorkspace` 的 `selected` 此前是 `items.find(...)`——`items` 是**当前视图过滤后的列表**。
左侧树能点开任意一篇（`App` 的 `onOpenItem` = `setBrowse(null)` + `workspace.open(id)`），
而当这一篇**不属于此刻的视图**（停在「工作」视图里点开「私事」下的文档；视图是最近编辑 / 收藏 / 标签）
时 `selected` 为 `null` → 正文区退回空占位，用户"点了树里的文档却看不到内容，得先切到那个文件夹再点一次"。

改法：`selected` 从 `allItems` 里按 `selectedId` 找，**再用 `canShowInList(item, gate)` 过一遍门禁**
（锁定时空间内条目、回收站条目仍为 `null`，正文区照旧占位）——与列表过滤同一处判定，不新写第二套。
回归用例 `test/notes-open-out-of-view.test.tsx`（3 条，含"锁定时打不开"）。

## 三、第 1 条与第 3 条的取舍（写清不装作没有）

- 第 1 条去掉的那一行原来还承担三件事：待办的「截止 + 优先级」、Memo 的「设为清单？」、
  笔记的「首行作标题 + 落点提示」。**能力都还在，只是搬去了「添加内容窗口」**（Memo / 待办视图的「添加」）；
  功能栏录入框的待办档现在按**默认值**发布（无截止、优先级「中」），Memo 档 `asTask` 恒 `false`。
  功能栏录入框的 `@` 属性菜单随之退出（`attributes` 传模块级空表；后期按用户口径由 `@` 统一接管属性设置）。
- 第 3 条不是"改个方向"而是**不能写死方向**：功能栏录入框在功能栏顶部（y≈116），一律向上弹会顶出视口；
  添加内容窗口的输入区上方只有标题、且 `.modal` 是 `overflow: hidden`，向上弹同样被裁。
  现在由 `menu-placement.ts` 量"锚点 + 最近的裁剪祖先"，先看哪边放得下、再取空间大的一侧，
  并把 `max-height` 压到可用空间内（矮而可滚动，好过被裁）；默认仍是**向上**（编辑器试验页那三处锚点在页面底部）。
  已知边界：菜单打开期间若窗口尺寸或滚动位置变化，**不重量**（关掉重开即可）——没做监听，记在这里。
