# Runbook（故障与限额处置）

| 项 | 值 |
|---|---|
| 适用范围 | 线上出问题时照着查。**一个故障一张卡**，从上往下找 |
| 权威级别 | 模块规则。限额数字以 `wiki/Menote-项目架构-v1.md` §十四 为准，本文是它们的处置视角 |
| 最后更新日期 | 2026-10-03 |

**先做这三步**（九成的问题到这里就定位了）：

```bash
curl -s https://你的域名/api/health                      # 1 Worker 活着吗
curl -s https://你的域名/api/auth/registration-state    # 2 库通吗
curl -sI https://你的域名/                              # 3 是不是 https
```

Cloudflare Dashboard → 你的 Worker → **Logs**（实时）与 **Metrics**（用量）是最重要的两个入口。

---

## 卡 A · 构建卡住 / 部署不出来

**症状**：Builds 面板停在 `Build failed to initialize and was timed out`，或新提交一直排队。

**根因（免费版硬限制）**：**只允许一个并发构建**。一个卡住的构建会堵住后面所有构建。

**处置**：

1. Dashboard → Worker → **Builds** → 找到卡住那条 → **Cancel**
2. 对最新提交点 **Retry**
3. 看 <https://www.cloudflarestatus.com> 有没有事故
4. 若 Retry 后仍卡：**本地跑一遍**确认不是代码问题——
   `pnpm install --frozen-lockfile && pnpm build && pnpm check:size`

**别做的事**：不要因为这个去改 `wrangler.jsonc` 的 secrets 门禁，也不要把迁移命令加进 deploy 脚本——见 `local-dev.md` §八，那两处都实测踩过。

---

## 卡 B · 503 且文案提到 `AUTH_PEPPER`

**症状**：注册 / 登录返回 503，提示缺机密。

**根因**：机密没配到**正在服务的那个 Worker**。预览 URL 和生产 URL 是**两个不同的 Worker**，机密要各配各的。

**处置**：Worker → Settings → Variables and Secrets → 确认 `AUTH_PEPPER` 存在且类型是 **Secret**。

**为什么不能用空密钥兜底**：密码校验值是 `HMAC(AUTH_PEPPER, 登录密钥)`，用空密钥算出来的值谁都能伪造出合法账号。所以这里是 fail-closed——宁可拒绝服务。

⚠️ **换 `AUTH_PEPPER` 的代价**：所有账号登不进去 + 已存的备份包裹键解不开。**设了就别换**。

## 卡 C · 前端能用，但注册/保存失败

**症状**：页面能开，登录/注册/保存报错。

**根因**：用 `http://` 打开的。浏览器只在**安全上下文**（`https://` 或 `localhost`）提供 WebCrypto。

**处置**：Worker → Settings → Edge Certificates → 打开 **Always Use HTTPS**。临时可用 `http://localhost` 排查。

**别误判成后端 bug**——这是环境问题。

---

## 卡 D · 顶栏一直"同步中"

**症状**：写不上去，顶栏不出"已同步"。

**逐条查**：

| 检查 | 怎么看 |
|---|---|
| 网络 | 浏览器 DevTools → Network，看 `POST /api/sync/push` 是否失败 |
| 服务端是否活着 | `GET /api/health` |
| 是否在限额里 | Metrics → 看 Errors 里有没有 `Invocation Statuses` 超限（见卡 E/F） |

**处置**：内容不会丢——写先进本机队列，联网后自动补传。限额类问题见下面两张卡。

---

## 卡 E · D1 写/读超限

**症状**：Metrics → Errors 出现 `D1_ERROR`（`overloaded` / `too much`），写入失败，界面报"服务暂时不可用"。

**免费版限额**（每日 00:00 UTC 重置）：

| 项 | 限额 |
|---|---|
| 读行数 | 5,000,000 / 天 |
| 写行数 | 100,000 / 天 |
| 存储 | 5 GB |

**处置，按性价比排**：

1. **先看是不是自己打爆的**：MCP 令牌可以调限速（设置 › MCP，默认 60 次/分钟）。某个 agent 死循环会飞快吃掉写额度——**去审计记录看有没有异常密集的调用**。
2. **同步每页拉 200 行**是硬上限（架构 §6.1），已是最省；不要为了"快点"调大。
3. **等待 UTC 零点重置**是最省事的止血。
4. 长期方案：升付费版，或减少设备数 / 降低同步频率。

**注意 `sync_seq` 推进也计入写行**——一次编辑至少 1 次写，且批量写会推多次。

## 卡 F · CPU 超限（10 ms / 请求）

**症状**：Metrics → Errors → **Invocation Statuses** 出现 `Exceeded CPU`；特定请求（多半是**大文档**）失败而小文档正常。

**免费版限额**：每请求 **10 ms CPU**。

**已知哪些操作最重**（架构 §14.2）：

| 操作 | 防护 |
|---|---|
| 2 MB 正文全文保存 | 原文走请求体不用 JSON；超限时客户端改用补丁 |
| 版本压缩（≤256 KB） | 超过 256 KB 不压缩 |
| MCP 小节解析（≤512 KB） | 超门槛直接拒绝，提示改用区间/游标 |

**处置**：让用户**把大文档拆小**是最直接的（正文硬上限 2 MB / 软上限 1 MB）。代码侧要优化的话，先按 `docs/modules/Menote-M7-性能预算校准-v1.md` §五 的清单实测定位，别凭感觉改。

## 卡 G · 子请求超限

**症状**：Cron 任务或某个接口报子请求超限；**定时备份**最容易撞。

**限额（免费版）**：

| 类别 | 限额 |
|---|---|
| **外部**（`fetch()` 到互联网：WebDAV / S3 / 第三方 API） | **50 / invocation** |
| **内部**（R2 / D1 / KV / DO 绑定） | **1000 / invocation** |

**注意两者差 20 倍**：备份推 800 个文件到 WebDAV 会撞**外部 50**，但同样数量的 R2 写入完全没问题。

**处置**：调小单批参数（架构 §十四 与备份设计 §二 的口径：**每轮一批、批 ≤40 外部 PUT、按配额续推**）。**不要**靠升限额硬扛——免费版这个数改不了。

---

## 卡 H · 每日请求超限（100,000 / 天）

**症状**：Metrics 显示当天请求数逼近上限；之后开始返回 Cloudflare 1015 错误（"error code 1015"）。

**根因**：请求数是**账户级**的（`workers.dev` 子域也算），不是单 Worker。

**处置**：查是谁在打——MCP 令牌、分享查看器、预览 URL 都可能被爬虫扫到。**撤销不认识的 MCP 令牌**是见效最快的一步。

---

## 卡 I · 附件上传失败

**逐条查**：

1. **绑定在不在**：Worker → Settings → Bindings → R2 `ATTACHMENTS`
2. **桶名对不对**：必须是 `menote-attachments`
3. **单个文件 ≤ 20 MB**
4. **账户有没有绑支付方式**：R2 桶的创建不豁免绑卡

---

## 卡 J · 忘记隐私密码

**处置**：设置 › 隐私锁 › 重置隐私密码。

⚠️ **后果必须先讲清**：重置会作废旧钥匙，**加密空间与单篇加密里的内容从此永久无法解开**。服务端没有钥匙、没有后门、没有找回途径。重置不影响登录密码、不影响其它普通笔记。

---

## 卡 K · MCP 连不上

**按这个顺序查**（服务端已经刻意不区分失败原因，所以只能这样排）：

| 查 | 怎么看 |
|---|---|
| 令牌还在不在 | 设置 › MCP，状态是不是「生效中」 |
| 有没有被撤销 | 同上；撤销**立即生效** |
| 过期了没 | 同上；过期令牌一律 401 |
| 是不是发了旧令牌 | 完整令牌**只在创建时显示一次**。丢了就撤销重建 |
| 权限够不够 | 令牌只读时调写工具会得到「没有 XX 权限」 |
| 是不是被限速 | 返回 429 + `-32029`，**等一分钟**；可在设置里调每分钟次数 |
| 地址对不对 | 设置 › MCP 页第一行就是地址，**不需要手动改** |
| 客户端配置 | 传输方式选 **Streamable HTTP**（默认）；认证选 **Bearer / 请求头** |

**一条极隐蔽的**：如果 MCP 端点**没被列进 `wrangler.jsonc` 的 `assets.run_worker_first`**，客户端拿到的是一份 HTML 而不是 JSON-RPC 响应——**现象是 HTTP 200 + 一堆 HTML**，很容易被误判成协议问题。本项目已把它列进去了（`/mcp` 与 `/mcp/*`），若你改了那个字段请记得加回来。

## 卡 L · 数据要恢复

**处置**：设置 › 备份与导出 → 从备份恢复（导入一个之前导出的 zip）。

**前提**：你有一个**之前导出的 zip**。没导过就恢复不了——这是唯一诚实的答案，所以**定期导出是硬要求**（见 `wiki/guides/使用说明.md` §五）。

**恢复后必做**：让所有人**重新登录**一次（旧会话可能指向已替换的数据），并抽查几篇笔记的正文与附件。
