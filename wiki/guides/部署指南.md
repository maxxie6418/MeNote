# 部署指南（从零到线上）

| 项 | 值 |
|---|---|
| 适用范围 | 把 Menote 部署成一个可用的线上实例（自己用或给家里人用） |
| 权威级别 | 模块规则。机制以 `wiki/Menote-项目架构-v1.md` §15.5 为准，本文把它展开成**点击级步骤** |
| 最后更新日期 | 2026-10-03（本文写的是**真跑通过**的配置，不是照模板抄的） |

> 本地开发看 `wiki/guides/local-dev.md`。那篇讲"改代码"，这篇讲"上线"。

## 一、两条路，选一条

| | A. 一键按钮（推荐给不熟 Git 的人） | B. 自己接 GitHub（推荐给以后要持续更新的人） |
|---|---|---|
| 做什么 | 点 [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/maxxie6418/MeNote)，它会**把仓库克隆一份到你自己的 GitHub 账户**并配好 Workers Builds | 在 Cloudflare 里 Workers & Pages → Create → 导入**你自己 fork 的那个仓库** |
| 适合 | 想赶紧用起来 | 打算长期跟着项目更新（推荐，**本项目的部署实践走的是这条**） |

**两条路之后的步骤完全一样**，从第二节开始读。

## 二、Workers Builds 的四个字段

Dashboard → 你的 Worker → **Settings → Builds & deployments**：

| 字段 | 填什么 |
|---|---|
| 生产分支 | `main` |
| **构建命令** | `pnpm run build` |
| **部署命令** | `npx wrangler deploy` |
| 根目录 | `/`（仓库根） |

**关于构建命令的两种写法**：本文写 `pnpm run build`（实测走通的）。`wiki/guides/local-dev.md` §六 与 README 写的是 `pnpm install --frozen-lockfile && pnpm build`。**两者都能用**，区别是：

- `pnpm run build` —— 依赖已经装好就直接构建。Workers Builds 会先跑一次 `pnpm install`（用 lockfile），所以够用。
- `pnpm install --frozen-lockfile && pnpm build` —— 显式再装一次。更保险，**更新依赖后建议用这个**。

**根目录必须是 `/`**。填成 `apps/web` 会导致 wrangler 找不到根目录的 `wrangler.jsonc`，构建在最后一步失败。

非 `main` 分支和 PR 会**自动拿到预览 URL**，改代码时先用预览验证再合并。

## 三、部署后必须做两件事

### 3.1 加机密 `AUTH_PEPPER`

Worker → **Settings → Variables and Secrets** → Add → 类型选 **Secret** → 名字填 `AUTH_PEPPER` → 值用这行命令生成：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

**保存后立即生效，不用重新构建。**

⚠️ **三条要紧的**：

1. **这个值设了就别换**。密码校验值是 `HMAC(AUTH_PEPPER, 你的登录密钥)`——换了之后**所有已有账号都登不进去**，同时已存的备份包裹键也解不开（"重置隐私密码"会中断）。两件事一起发生。
2. **只需要这一个机密**。隐私锁的备份包裹键由它**域分离派生**，不需要第二个。老部署上如果还留着 `BACKUP_CRED_KEY`，代码已经不读它，可以直接删。
3. **没配之前能做什么**：能看到"库里还没有用户"，但**注册和登录会返回 503** 并提示缺哪一项。这是刻意的——宁可拒绝服务，也绝不用空密钥去算密码校验值。

### 3.2 确认 R2 桶在

Worker → **Settings → Bindings**，应能看到 R2 绑定 `ATTACHMENTS` 指向桶 `menote-attachments`。

**没看到的话**：Storage & R2 → Create bucket，名字**必须是 `menote-attachments`**（`wrangler.jsonc` 里按名字绑定，名字对不上就是没绑上）。绑完附件功能才能用——笔记本身不需要 R2。

> **一条会绊人的**：创建 R2 桶**不豁免绑卡**。Cloudflare 账户没绑支付方式时，桶可能建不出来，于是整个部署失败。先把 R2 建好再部署，或者先做 D1-only 部署（笔记能用，附件不能）。

## 四、顺手打开 Always Use HTTPS

Worker → **Settings → Edge Certificates** → 打开 **Always Use HTTPS**。

**不打开的后果**：家人用 `http://` 打开网站，浏览器不提供加密能力，于是**注册不了、保存不了**，而界面只显示一句"请改用 https 打开"。很容易被当成 bug 报上来。

## 五、部署完怎么确认成了（诊断三连）

三个请求**都不需要登录**，按顺序敲：

```bash
# 1. Worker 活着吗
curl -s https://你的域名/api/health
# 期望：{"ok":true,...}

# 2. 库是空的吗
curl -s https://你的域名/api/auth/registration-state
# 期望：{"open":false,"has_users":false}   ← 空库，可以注册第一个管理员

# 3. 机密生效了吗
curl -s -X POST https://你的域名/api/auth/prelogin \
  -H 'Content-Type: application/json' -H 'X-Menote: 1' -d '{"username":"x"}'
# 期望：200 且带 auth_salt  → 机密 OK
# 若 503 且文案含 AUTH_PEPPER → 机密没配到正在服务的这个 Worker 上
```

**表结构不用手工迁移**——第 1 个请求触发运行时自愈建表（架构 §15.4）。所以第 1 条返回 200 就说明建表已经跑过了。

## 六、验收清单

部署完照着过一遍，全过就算成了：

- [ ] `GET /api/health` 返回 `{"ok":true}`
- [ ] 打开网站，**用 http 访问会被自动跳 https**（第四节开了 Always Use HTTPS）
- [ ] **注册第一个账号成功**（空库时 `has_users:false`）
- [ ] 新建一篇笔记，**刷新页面内容还在**（说明落库成功，不只是本地缓存）
- [ ] 打开另一台设备的浏览器，登录能看到刚才那篇（说明同步通了）
- [ ] 上传一个小附件并插进笔记（**验证 R2 真的绑上了**）
- [ ] 设置 › 关于 里版本号是预期的
- [ ] 定时任务在跑：等半小时后，Worker 日志里能看到每日维护的记录

## 七、会上绊你的几件事（都是真踩过的）

### 7.1 构建卡在 "Build failed to initialize and was timed out"

**免费版只允许一个并发构建**。一个卡住的构建会**堵住后面所有构建**，此时新提交会一直排队直到失败。

处置：Cloudflare Dashboard → 你的 Worker → **Builds** → 找到卡住那条 → **Cancel** → 对最新一次提交点 **Retry**。然后看 <https://www.cloudflarestatus.com> 有没有事故。

**本地先自查一遍**再点 Retry，能省掉一次往返：

```bash
pnpm install --frozen-lockfile && pnpm build && pnpm check:size
```

三条都过，基本可以确定是平台侧的问题而不是代码。

### 7.2 部署成功但界面报错

按 §五 的诊断三连走，**九成能定位**：

| 现象 | 多半是 |
|---|---|
| `/api/health` 不通 | 部署根本没成功，回 Builds 看日志 |
| `has_users:true` 但你确定没注册过人 | 用了旧的 D1 库（`wrangler.jsonc` 不写 ID，按名绑定；重名会命中老库） |
| 注册/登录 503，文案含 `AUTH_PEPPER` | 机密没配到**正在服务的那个 Worker**（预览 URL 和生产 URL 是两个 Worker） |
| 界面能开但保存失败 | 用 http 打开的，见 §四 |

### 7.3 改了代码但线上没变

- 确认提交在 **`main`** 分支（其它分支只有预览 URL）；
- Workers Builds 面板看最新一次构建的状态，**Builds 页面**不是 Settings 里那个开关；
- 硬刷浏览器（Ctrl/Cmd + Shift + R）——前端资源有缓存。

## 八、后续更新

推送到 `main` 就自动重新部署，不需要在 Dashboard 点任何东西。

**推之前本地跑一遍**（CI 也会跑同样的四条）：

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm check:size
```
